# 其他项目组件吸收矩阵

> 文档编号：TS-AOS-ADOPT-010  
> 原则：天枢维护总框架；各项目按组件吸收；领域能力保留在各项目。

## 一、接入模式

### M1：Embedded Runtime

项目直接嵌入天枢Runtime包，适合Node.js项目和强协同场景。

### M2：Tianshu Service

项目通过HTTP、CLI、MCP或消息协议调用天枢，适合Python、桌面端和独立部署项目。

### M3：Protocol Adoption

项目不运行完整天枢，只采用Claim、Receipt、Authorization、Evidence、Outcome等协议。

### M4：Independent Inspiration

项目独立实现适合自身的机制，同时保持可映射到天枢协议。

## 三、AWKN Memory OS

### 定位

独立记忆模块，可挂载到天枢，也可被其他项目直接调用。

### 吸收组件

| 组件 | 深度 | 方式 |
|---|---:|---|
| C01 | 中 | 复用DLP、身份和Persistence Guard协议 |
| C03 | 高 | Claim Lineage、Context Manifest、Freshness、权限 |
| C04 | 中 | Rule治理与Policy Authority对齐 |
| C08 | 高 | Consumption、Citation、Outcome Attribution |
| C09 | 最高 | Transaction、CAS、Tombstone、Dependency、Evolve Rule |

### Memory OS保留的独立能力

- Core API与SDK；
- 长期Claim和Experience；
- Context Ledger；
- Immutable Render；
- 跨项目权限；
- 持久化事务；
- Rule治理；
- Clean Install和Release Gate。

### 禁止重复建设

- 天枢不复制Memory OS完整长期存储；
- Memory OS不接管天枢Goal、Tool、Model和Delivery路由。

### 吸收组件

| 组件 | 深度 | GUNDAM落点 |
|---|---:|---|
| C01 | 中 | 本地输入、文件和隐私入口 |
| C02 | 中 | 桌面任务L0—L4识别 |

| C05 | 高 | Codex模型路由、工具权限和累计风险 |
| C06 | 高 | 主动任务证据增量和中断预算 |
| C07 | 高 | 桌面通知、文件、窗口、任务交付 |
| C08 | 高 | 用户可见执行状态和结果 |
| C09 | 中 | 记忆候选和桌面行为学习 |
| UI1 | 最高 | Trust Center、授权中心、记忆中心、恢复中心 |

### GUNDAM专属能力

- 桌宠形态；
- 情绪和关系交互；
- Codex工作流；
- Tauri桌面窗口；

- Windows安装包和Sidecar。

### 关键边界

GUNDAM可以完整吸收协议，但其实现和UI不成为其他项目的强制依赖。

### 吸收优先级

| 优先级 | 组件 | Value领域扩展 |
|---|---|---|
| P0 | C01 | 行情、公告、财务数据来源可信化 |
| P0 | C03 | Market Claim、Freshness Contract、Source Authority |
| P0 | C05 | 数据源、模型和工具路由；交易风险 |
| P0 | C08 | 分离研究结果、用户决定、真实交易和收益结果 |
| P0 | C09 | 投资偏好、交易纪律和结果归因写入门 |
| P1 | C02 | 市场分析L0、选股L1、策略回测L2、盘中监控L3 |
| P1 | C06 | 每轮新证据、缠论结构验证和策略切换 |
| P1 | C07 | 盘中简报、条件单草案、报告和驾驶舱 |
| P1 | C04 | 投资猎手Policy、缠论Skill和Stop Doing List |

### 必须新增的领域对象

- `MarketDataReceipt`
- `QuoteFreshnessContract`
- `InvestmentThesisClaim`
- `TradeRecommendation`
- `UserTradeDecision`
- `ExecutionObservation`
- `PositionOutcome`

### 领域Gate

- 市场时间Gate；
- 行情时效Gate；
- 数据源冲突Gate；
- 仓位和风险纪律Gate；
- 11日线和缠论结构Gate；
- Capability Preservation Gate。

### 关键工程风险

Value近期出现过自动Lint修复误删有效功能的情况。需要强制：

- 路由清单对比；
- 函数能力清单；
- API Schema快照；
- 关键行为Golden Case；
- 删除功能的迁移证据。

### 吸收组件

| 组件 | 深度 | 作用 |
|---|---:|---|
