# 核心架构与领域模型

> 文档编号：TS-AOS-ARCH-001  
> 版本：v0.2 Draft  
> 范围：仅 `AWKN-Lab/tianshu` 内部运行时

## 一、架构目标

本架构将天枢现有运行时重组为九个核心组件和五个横切能力。组件通过结构化契约协作，减少隐式 Prompt、环境变量和自由文本承担关键状态的情况。

强制边界：

- C01—C09全部属于天枢内部实现；
- 不发布为其他业务仓库的公共Runtime或SDK；
- 不要求其他仓库兼容天枢Schema；
- 唯一跨仓运行关系为 `AWKN-Memory-OS` 的 `MemoryBackend` 挂载；
- GitHub、Drive、Web和其他仓库文件在天枢中只属于外部数据源。

## 二、九个核心组件

| 编号 | 组件 | 责任 | 工程动作 |
|---|---|---|---|
| C01 | Trusted Input Gateway | 输入可信化、身份、脱敏、注入清洗、风险初筛 | NEW |
| C02 | Intent & Goal Router | 意图、L0—L4、Goal、澄清价值和停止策略 | UPGRADE |
| C03 | Context Planner | Claim检索、时效、权限、Token和Context Manifest | UPGRADE |
| C04 | Policy & Skill Compiler | Policy/Skill选择、冲突、编译和冻结 | NEW + UPGRADE |
| C05 | Tool & Model Broker | 模型、工具、供应商、授权和累计风险 | UPGRADE |
| C06 | Evidence-Gain Loop | 预期证据、执行、偏差、策略切换和停止 | UPGRADE |
| C07 | Delivery Router | Chat、File、Visual、App、外部系统和计划任务 | NEW |
| C08 | Evidence & Outcome | Receipt、Trace、Outcome、归因和校准 | UPGRADE |
| C09 | Memory Write & Evolve | 记忆门、候选、回放、晋级、隔离和回滚 | UPGRADE |

## 三、五个横切能力

1. **Identity & Tenant Boundary**：用户、组织、项目、会话和执行主体；
2. **Authorization**：工具、数据、模型和外部系统授权；
3. **Observability**：Trace、Span、Metric、Log和Receipt；
4. **Persistence & Recovery**：Event Store、Snapshot、Outbox和幂等；
5. **Version & Governance**：Schema、Policy、Skill、Prompt、Model Route和Rule版本。

| 新组件 | 现有代码 | 处理方式 |

### 6.1 ExecutionState

```text

→ COMPILED
```

```ts
export interface Claim {
  schema: 'awkn-claim/v2';
  claimId: string;
  content: string;
  contentHash: string;
  originator: 'human' | 'assistant' | 'system' | 'external';
  speaker: 'human' | 'assistant' | 'system' | 'tool';
  claimType:
    | 'fact'
    | 'preference'
    | 'decision'
    | 'goal'
    | 'constraint'
    | 'hypothesis'
    | 'recommendation'
    | 'prediction'
    | 'observation';
  epistemicStatus:
    | 'proposed'
    | 'asserted'
    | 'confirmed'
    | 'derived'
    | 'disputed'
    | 'superseded'
    | 'expired';
  confirmationScope: 'none' | 'direction' | 'option' | 'field_level';
  sourceRefs: SourceRef[];
  derivedFrom: string[];
  authority: number;
  confidence: number;
  sensitivityClass: string;
  validFrom?: string;
  validUntil?: string;
  projectId?: string;
  userId?: string;
}
```

### 7.1 Claim升级状态机

```text
PROPOSED
→ ASSERTED
→ DIRECTION_CONFIRMED
→ OPTION_CONFIRMED
→ FIELD_CONFIRMED
→ OBSERVED
→ SUPERSEDED / DISPUTED / EXPIRED
```

约束：

- Assistant Recommendation不能直接进入Human Decision；
- Summary Claim不能替代原始Human Message；
- External Fact不能写成User Fact；
- 简单正反馈只允许升级到`DIRECTION_CONFIRMED`；
- 用户明确字段才可进入`FIELD_CONFIRMED`。

## 九、Receipt体系

| Receipt | 证明内容 |
|---|---|
| InputReceipt | 输入来源、Hash、清洗和风险结果 |
| IntentReceipt | L0—L4路由与理由 |
| ContextReceipt | 检索候选和上下文选择 |
| PolicyReceipt | Policy版本、冲突和编译结果 |
| SkillReceipt | Skill选择、版本和前置条件 |
| ModelRouteReceipt | 请求模型、实际模型和fallback |
| ToolAuthorizationReceipt | 授权范围和有效期 |
| ToolExecutionReceipt | 工具真实执行结果和副作用 |
| GateReceipt | Gate结果和证据 |
| DeliveryReceipt | 交付位置、Hash和状态 |
| OutcomeReceipt | 执行、采用和业务结果 |
| MemoryWriteReceipt | 写入原因、目标后端和版本 |
| EvolutionReceipt | 候选、回放、晋级和发布 |

## 十、标识与关联规则

- `traceId`：一次端到端请求；
- `executionId`：一次主链执行；
- `goalId`：一个长期目标；
- `runId`：一次Goal执行尝试；
- `stepId`：Run内步骤；
- `claimId`：声明；
- `evidenceId`：证据；
- `deliveryId`：交付；
- `outcomeId`：结果；
- `candidateId`：进化候选。

所有子对象必须追溯到`executionId`和`traceId`。

## 十二、依赖规则

```text
C01 → C02 → C03 → C04 → C05 → C06 → C07 → C08 → C09
```

允许回路：

- C06请求C03增补上下文；
- C06请求C05切换模型或工具；
- C08向C06反馈结果；
- C09生成候选后进入Evolve回放；
- Evolve产物发布后更新C04 Registry。

禁止回路：

- Memory直接改写ACTIVE Policy；
- Tool直接写入长期记忆；
- Model Provider直接决定授权；
- Delivery Adapter直接声明业务Outcome；
- 天枢内部调用方绕过Broker执行高风险工具；
- C01—C09调用其他业务仓库作为实现依赖。

```text
GATE_FAILED

OUTCOME_UNKNOWN
MEMORY_WRITE_REJECTED
EVOLUTION_REPLAY_FAILED
```

每个错误必须声明：

- 是否可重试；
- 重试是否需要新幂等键；
- 是否需要用户操作；
- 是否允许降级；
- 是否产生部分结果；
- 是否需要补偿。

## 十四、迁移策略

### REUSE

- `AgentLoop.runL1/runL2`；
- GoalManager；
- EventStore；
- Tool Registry；
- LLM Provider；
- MemoryBackend；
- Trace；
- ArtifactBundle；
- Evolve Candidate生命周期。

### UPGRADE

- `LlmRouter`由ModelBroker调用；
- `ToolPolicy`由ToolBroker调用；
- `MemoryRouter`由ContextPlanner和MemoryWriteGate调用；
- `quality-gates`作为Evidence Loop的Gate Adapter。

### NEW

- ExecutionEnvelope；
- Input Gateway；
- Claim Ledger；
- Context Manifest；
- Policy Compiler；
- BrokerPlan；
- EvidenceDelta；
- Delivery Router；
- Outcome Record。

### DEPRECATE

- LLM响应完成后无条件沉淀交互；
- 只通过环境变量表达长期授权；
- 自由文本传递关键修复上下文；
- 无Route Receipt的模型fallback；
- Delivery与Execution共用单一成功状态。

## 十五、独立性验收

- `package.json`无其他AWKN业务仓库包依赖；
- 源码无其他AWKN业务仓库Import；
- 环境变量无其他项目服务地址；
- CI不要求其他业务仓库构建产物；
- Release Manifest只声明天枢和可选Memory OS兼容版本；
- GitHub等工具读取其他仓库时，仅记录为外部Source Ref。
