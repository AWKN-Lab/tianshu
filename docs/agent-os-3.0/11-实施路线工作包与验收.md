# 实施路线、工作包与验收

> 文档编号：TS-AOS-PLAN-011  
> 版本：v0.2 Draft  
> 范围：仅 `AWKN-Lab/tianshu` 与 AWKN Memory OS挂载协议  
> 策略：契约先行、增量迁移、双轨验证、单仓发布

## 一、实施边界

本计划只安排天枢仓库的代码、Schema、测试和发布，以及天枢与 Memory OS 的挂载协议升级。

明确排除：

- GUNDAM接入；
- Value接入；
- win接入；
- Mr.Mont、life-choice接入；
- annie、subtitle、awkn-Feel接入；
- solo-skill-booster接入；
- 任何其他仓库的Adapter、Pilot、SDK或兼容性工作。

其他项目的进化应在各自仓库单独建立PRD、工作包和Release Gate。

## 二、实施原则

1. 现有 Engine v2 保持可运行；
2. 新能力通过天枢内部 Adapter 包裹旧模块；
3. 先冻结 Schema 和 Receipt，再修改主链；
4. 每个工作包有独立验收和回滚点；
5. 新旧路径通过 Feature Flag 并行；
6. 高影响迁移使用 Shadow Mode；
7. 每次发布包含 Manifest、测试证据和兼容性报告；
8. 文档完成不等于代码完成，所有状态以机器证据为准；
9. 除 Memory OS 外，不增加任何跨仓库运行依赖。

## 五、WP-AOS-00 Baseline Freeze

### 目标

冻结当前 `main` 作为 Agent OS 3.0 迁移基线。

### 交付

- 精确 Commit SHA；
- `npm ci` 报告；
- `npm run check` 报告；
- 当前 Schema 版本；
- CLI 命令快照；
- Provider、Tool、Gate、Memory Backend和Event类型清单；
- 当前性能基线；
- 已知失败清单；
- 外部仓库依赖清单。

### 验收

- 干净环境可复现；
- 测试数量和结果可核对；
- 关键能力清单生成Hash；
- 后续能力减少可以被检测；
- 外部运行依赖只有可选 Memory OS。

## 七、WP-AOS-02 Trusted Input Gateway

### 改造点

- CLI、Chat、Cron、Hook和API统一入口；
- 公共DLP与脱敏；
- 文件存在性和Hash；
- Actor/Project Scope；
- Input Receipt。

### Feature Flag

```text
AWKN_INPUT_GATEWAY_V1=0|shadow|enforce
```

### Shadow指标

- 新旧输入差异；
- Redaction数量；
- 错误拦截率；
- P95延迟；
- 误拦截样本。

### 验收

- 天枢所有入口均生成Input Receipt；
- 文件缺失不得伪造读取成功；
- Secret不进入Trace；
- 高风险入口失败时禁止放宽执行。

## 十、WP-AOS-05 Context Planner

### 交付

- Context Query Plan；
- 天枢内部Source Adapters；
- Utility Score；
- Freshness Contract；
- Token Allocator；
- Context Manifest；
- Immutable Render绑定。

### 允许来源

- 当前对话；
- 天枢历史对话或本地轨迹；
- 天枢仓库文件；
- 用户授权的GitHub、Drive和Web来源；
- 天枢Local Memory；
- 挂载的Memory OS；
- 天枢Policy与Skill Registry。

其他业务仓库不能作为天枢运行组件。天枢通过普通GitHub读取工具访问某个仓库文件时，该仓库只是外部数据源，不构成运行依赖。

### Shadow Mode

现有Memory Enrichment继续生效，同时生成新Manifest但不注入，比较：

- 选中项差异；
- Token差异；
- 任务结果差异；
- 敏感项差异；
- 过期项差异。

- 路由评分；

### Tool Broker

## 二十一、WP-AOS-19 Compatibility, Hardening & RC

### 兼容矩阵

| 老接口 | 新接口 | 过渡方式 |
|---|---|---|
| `runL1(string)` | `runL1(TrustedInput)` | Overload + Adapter |
| `runL2(string)` | `runGoal(ExecutionEnvelope)` | 保留旧CLI |
| `LlmRouter.chat()` | `ModelBroker.execute()` | Router作为内部Adapter |
| `ToolRegistry.execute()` | `ToolBroker.execute()` | Registry作为内部Adapter |
| `compileAndRender(query)` | `ContextPlanner.plan()` | 旧路径Shadow |
| `rememberResponse()` | `MemoryWriteGate.evaluate()` | Feature Flag |

### Feature Flags

```text
AWKN_INPUT_GATEWAY_V1
AWKN_INTENT_ROUTER_V1
AWKN_CONTEXT_PLANNER_V1
AWKN_POLICY_COMPILER_V1
AWKN_BROKER_V1
AWKN_EVIDENCE_LOOP_V1
AWKN_DELIVERY_ROUTER_V1
AWKN_OUTCOME_V1
AWKN_MEMORY_WRITE_GATE_V1
AWKN_EVOLVE_V2
```

值：

```text
0
shadow
enforce
```

### 加固内容

- Shadow差异收敛；
- Event Replay一致性；
- Provider失败与fallback；
- Tool部分成功和副作用验证；
- Memory OS不可用和Outbox积压；
- 长循环No-Gain停止；
- 权限撤销；
- Linux与Windows；
- 性能回归；
- 外部仓库依赖扫描。

## 二十二、测试层级

### Unit

纯函数、评分、状态机、Hash和冲突解析。

### Contract

Schema、天枢内部Adapter、Receipt和Memory OS协议。

### Integration

天枢主链组件组合、Memory OS、Provider和Tool。

### Replay

天枢历史Run、失败模式和候选规则。

### Golden

固定天枢任务案例和预期ExecutionEnvelope。

### Chaos

Provider失败、Memory OS失败、Outbox损坏、网络超时、部分成功和恢复。

### Security

身份、授权、敏感路径、数据外发和输入污染。

### Independence

必须增加：

- package依赖扫描；
- import路径扫描；
- 环境变量扫描；
- 网络端点扫描；
- CI配置扫描；
- 发布Manifest扫描。

验收目标：除Memory OS可选端点外，没有其他AWKN业务仓库的运行依赖。
