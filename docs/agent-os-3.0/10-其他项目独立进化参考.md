# 其他项目独立进化参考

> 文档编号：TS-AOS-INDEPENDENT-010  
> 版本：v0.2 Draft  
> 性质：机制研究参考，不构成接入方案

## 一、强制边界

除 `AWKN-Memory-OS` 可以通过 `MemoryBackend` 挂载到天枢外，其他仓库全部独立运行、独立开发、独立发布。

本文件中的“吸收”只表示吸收设计思想和工程机制，不表示：

- 复用天枢代码；
- 嵌入天枢 Runtime；
- 调用天枢 Service；
- 使用天枢 SDK；
- 兼容天枢 Schema；
- 订阅天枢 Registry；
- 共用天枢 Feature Flag；
- 共用天枢数据库、Trace、Memory、Policy 或发布流程。

每个项目应在自己的仓库中重新定义：

- 本地领域模型；
- 本地接口和 Schema；
- 本地状态机；
- 本地 Gate；
- 本地工具与模型路由；
- 本地记忆边界；
- 本地测试和 Release Gate。

## 十二、独立项目验收模板

每个项目分别回答：

1. 项目要解决的核心问题；
2. 选择吸收哪些机制思想；
3. 在本仓库如何重新定义对象和Schema；
4. 本地身份和数据边界；
5. 本地工具副作用和授权；
6. 本地模型路由要求；
7. 本地 Claim、Evidence 和 Outcome；
8. 本地记忆写入边界；
9. 本地失败恢复；
10. 本地契约测试和上线 Gate；
11. 如何证明没有天枢代码、服务或协议依赖。

## 十三、最终原则

```text
机制可以互相启发
代码不共享
运行时不共享
协议不强制共享
发布不耦合
数据不互通
权威不跨仓库
```

Memory OS 挂载天枢是唯一例外，并由专门协议文档管理。
