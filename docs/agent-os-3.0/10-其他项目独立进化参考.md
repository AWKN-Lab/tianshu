# 其他项目可用进化方向

> 文档编号：TS-AOS-EVOLUTION-010  
> 版本：v0.3 Draft  
> 性质：独立项目能力升级参考

## 一、使用方式

各项目根据自身产品定位、技术栈和业务目标，选择适合的机制，并在本项目仓库内完成领域模型、Schema、状态机、Gate、工具路由、模型路由、记忆策略、测试体系和发布流程。

本文件关注三个问题：

1. 哪些机制值得吸收；
2. 吸收后形成什么产品能力；
3. 如何在各项目内落成可验收的工程对象。

## 十一、CosmoSpark、Pri和其他探索项目

产品边界冻结前，建议先建立：

- 产品定位；
- 用户和核心场景；
- 输入与输出；
- 数据类型；
- 工具与副作用；
- 本地状态机；
- 本地Gate；
- 交付形式；
- 记忆策略；
- 测试体系；
- Release Gate。

完成基础定义后，再从R01—R09中选择优先机制。

## 十二、独立项目实施模板

每个项目分别形成一份实施文档：

1. 产品目标；
2. 本期选择的机制；
3. 本地领域对象与Schema；
4. 本地状态机；
5. 本地身份和数据范围；
6. 本地工具与模型路由；
7. 本地Claim、Evidence和Outcome；
8. 本地记忆策略；
9. 本地恢复机制；
10. 本地契约测试；
11. 本地Release Gate；
12. 版本路线和验收指标。

## 十三、建议推进顺序

```text
第一阶段：Value、win、GUNDAM
第二阶段：life-choice、annie、subtitle
第三阶段：awkn-Feel、solo-skill-booster
第四阶段：CosmoSpark、Pri及新项目
```

排序依据：业务价值、当前工程成熟度、风险收益比和可验证程度。
