# 状态机、事件与事务边界

> 文档编号：TS-AOS-STATE-015  
> 版本：v1.0 Draft  
> 关联：PR #25、Issue #30  
> 范围：Execution、Goal、Run、Step、Authorization、Delivery、Outcome、Claim、Memory、Evolve

## 一、冻结决定

1. `Execution DELIVERED` 不允许返回 `RUNNING`；后续修复创建新 Run，必要时创建新 Execution 并引用原 Execution；
2. `PARTIAL` 是当前 Run 或 Delivery Attempt 的终态；恢复通过新 Attempt 表达；
3. Goal 达成的唯一授权主体为 `GoalJudgeService`；
4. Tool 外部调用成功但验证失败时，状态进入 `SIDE_EFFECT_UNCERTAIN` 或 `PARTIAL`，禁止自动重试不可逆动作；
5. Receipt 与业务状态在同一事务内提交；关键 Receipt 写入失败阻断状态转换；
6. Event 与本地投影在同一 SQLite 事务中写入；
7. 天枢与 Memory OS 不使用分布式事务，使用本地提交 + Authority Outbox + 补偿；
8. 所有状态机由代码枚举和转换矩阵驱动，禁止依赖自由文本。

## 二、统一转换命令

```ts
interface TransitionCommand<T> {
  aggregateType: string;
  aggregateId: string;
  expectedRevision: number;
  from: string[];
  to: string;
  actor: ActorRef;
  reasonCode: string;
  payload: T;
  receiptIds: string[];
  idempotencyKey: string;
}
```

执行顺序：

```text
校验 Actor / Policy / Authorization
→ 校验 from 与 expectedRevision
→ 校验 Required Receipt
→ 写 Domain Event
→ 更新 Projection
→ 写关联表
→ Commit
```

任何一步失败，本地事务整体回滚。

## 三、Execution 状态机

### 3.1 正常主链

```text
RECEIVED
→ TRUSTED
→ ROUTED
→ CONTEXT_READY
→ COMPILED
→ AUTHORIZED
→ RUNNING
→ DELIVERING
→ DELIVERED
→ OUTCOME_PENDING
→ OUTCOME_RECORDED
→ CLOSED
```

### 3.2 分支状态

```text
BLOCKED
WAITING_USER
WAITING_AUTHORIZATION
RETRYING
DEGRADED
PARTIAL
FAILED
CANCELLED
```

### 3.3 转换矩阵

| From | To | Actor | 前置条件 | Required Receipt/Event |
|---|---|---|---|---|
| 无 | RECEIVED | Input Gateway | InputEnvelope 校验 | InputReceived Event |
| RECEIVED | TRUSTED | Input Gateway | 清洗、身份、风险完成 | InputReceipt |
| RECEIVED | BLOCKED | Input Gateway | 注入、权限或敏感输入阻断 | Failure InputReceipt |
| TRUSTED | ROUTED | Intent Router | IntentDecision 生成 | IntentReceipt |
| ROUTED | WAITING_USER | Intent Router | 高影响字段缺失 | Clarification Receipt |
| ROUTED | CONTEXT_READY | Context Planner | Manifest 可用或健康空结果 | ContextReceipt |
| CONTEXT_READY | COMPILED | Compiler | Policy/Skill Bundle 冻结 | CompilerReceipt |
| COMPILED | WAITING_AUTHORIZATION | Broker | 外部写入或风险升级 | AuthorizationRequestReceipt |
| COMPILED | AUTHORIZED | Broker | 无需授权或 Token 激活 | AuthorizationReceipt |
| AUTHORIZED | RUNNING | Coordinator | Run 创建 | RunStarted Event |
| RUNNING | RETRYING | Evidence Loop | 可恢复偏差 | CycleReceipt |
| RUNNING | WAITING_USER | Goal Loop | 需要用户决定 | GoalPauseReceipt |
| RUNNING | WAITING_AUTHORIZATION | Broker | Token 缺失、过期或风险升级 | AuthorizationRequestReceipt |
| RUNNING | DEGRADED | Coordinator | 允许的 Provider/Memory 降级 | DegradationReceipt |
| RUNNING | DELIVERING | Goal Judge | Goal ACHIEVED、交付前置满足 | GoalJudgementReceipt |
| DELIVERING | DELIVERED | Delivery Router | Primary Delivery 成功 | DeliveryReceipt |
| DELIVERING | PARTIAL | Delivery Router | 部分交付成功 | Partial DeliveryReceipt |
| DELIVERING | FAILED | Delivery Router | Primary Delivery 失败 | Failure DeliveryReceipt |
| DELIVERED | OUTCOME_PENDING | Outcome Recorder | 当前只具备执行/交付结果 | OutcomeReceipt |
| OUTCOME_PENDING | OUTCOME_RECORDED | Outcome Recorder | 获得后续观测 | OutcomeObservationReceipt |
| DELIVERED/OUTCOME_* | CLOSED | Coordinator | 写入门完成或明确跳过 | ClosureReceipt |
| 非终态 | CANCELLED | User/System | 取消有效 | CancellationReceipt |
| 非终态 | FAILED | Coordinator | 不可恢复失败 | FailureReceipt |

### 3.4 终态

Execution 终态：

```text
CLOSED
PARTIAL
FAILED
CANCELLED
BLOCKED
```

`DELIVERED` 是交付完成状态，仍需进入 Outcome/Closure。终态修改只能追加 Observation、Tombstone 或新 Execution 引用，不能原地恢复。

## 四、Goal 状态机

```text
DRAFT
→ ACTIVE
→ PAUSED
→ ACTIVE
→ ACHIEVED

ACTIVE → BLOCKED
ACTIVE → FAILED
ACTIVE → CANCELLED
PAUSED → CANCELLED
BLOCKED → ACTIVE   # 阻塞解除并创建恢复 Receipt
```

| 状态 | 含义 |
|---|---|
| DRAFT | GoalSpec 未冻结 |
| ACTIVE | 可以创建 Run |
| PAUSED | 等待用户、授权、外部状态或人工审核 |
| BLOCKED | 前提、能力、策略或协议阻断 |
| ACHIEVED | GoalJudge 给出 ACHIEVED |
| FAILED | 停止策略判定无法完成 |
| CANCELLED | 用户或治理主体取消 |

### 4.1 Goal Judge

Goal Judge 输入：

- GoalSpec；
- Required Acceptance 评估；
- Required Evidence；
- Constraint 评估；
- Gate Receipt；
- Delivery 前置条件；
- 当前 Policy Bundle。

输出 `GoalJudgement`。只有以下条件全部成立才能 ACHIEVED：

```text
Required Acceptance 全部 PASS
AND Required Evidence 新鲜且等级达标
AND Blocking Constraint 全部 PASS
AND Blocking Gate 全部 PASS
AND 无 ACTIVE Policy Block
AND Primary Delivery 前置条件可满足
```

模型 Reviewer 只能提供一个 Gate Receipt，不能独立更新 Goal 状态。

## 五、Run 与 Step

### 5.1 Run

```text
CREATED
→ RUNNING
→ RETRYING
→ RUNNING
→ SUCCEEDED

RUNNING → WAITING_USER
RUNNING → WAITING_AUTHORIZATION
RUNNING → PAUSED
RUNNING → PARTIAL
RUNNING → FAILED
RUNNING → BUDGET_EXCEEDED
RUNNING → POLICY_BLOCKED
RUNNING → CANCELLED
```

Run 终态：`SUCCEEDED | PARTIAL | FAILED | BUDGET_EXCEEDED | POLICY_BLOCKED | CANCELLED`。

Run `SUCCEEDED` 表示本次执行尝试完成并通过 Goal Judge，不自动代表 Business Outcome 成功。

### 5.2 Step

```text
PLANNED
→ AUTHORIZED
→ RUNNING
→ VERIFYING
→ SUCCEEDED
```

分支：

```text
WAITING_AUTHORIZATION
BLOCKED
FAILED
PARTIAL
SIDE_EFFECT_UNCERTAIN
COMPENSATING
COMPENSATED
CANCELLED
```

Tool Step 必须在调用前产生 PlannedAction 和 Authorization Decision。

## 六、Tool 外部副作用 Saga

### 6.1 标准流程

```text
Action Planned
→ Policy Check
→ Authorization Reserve
→ Intent Receipt committed
→ External Call
→ Completion Observation
→ Side-effect Verification
→ Completion Receipt committed
→ Authorization consumed
```

### 6.2 结果组合

| 外部调用 | 验证 | 本地状态 | 动作 |
|---|---|---|---|
| 失败且确认无副作用 | 不适用 | FAILED | 可按 Policy 重试 |
| 成功 | PASS | SUCCEEDED | 消耗授权 |
| 成功 | FAIL，动作可补偿 | COMPENSATING | 执行补偿 |
| 成功 | FAIL，动作不可补偿 | SIDE_EFFECT_UNCERTAIN | 暂停并人工介入 |
| 超时，外部状态未知 | UNKNOWN | SIDE_EFFECT_UNCERTAIN | 先查询外部状态，禁止盲重试 |
| 部分成功 | PARTIAL | PARTIAL | 记录成功子项和失败子项 |

### 6.3 补偿

补偿动作也需要：Policy、Authorization、Idempotency、Receipt 和 Verification。补偿失败不得覆盖原副作用记录。

## 七、Authorization 状态机

```text
PENDING
→ ACTIVE
→ CONSUMED

ACTIVE → REVOKED
ACTIVE → EXPIRED
ACTIVE → CONSUMED
PENDING → REVOKED
```

使用计数内部状态：

```text
available = maxUses - usedCount - reservedCount
```

预占在本地事务内执行。外部副作用状态未知时，预占不得释放，Authorization 状态保持 ACTIVE 或转为 CONSUMED，具体由 Policy 决定并记录 Receipt。

## 八、Delivery 状态机

```text
PLANNED
→ RUNNING
→ VERIFYING
→ SUCCEEDED
```

分支：`PARTIAL | FAILED | CANCELLED | SIDE_EFFECT_UNCERTAIN`。

冻结规则：

- 用户要求文件时，聊天文本不能替代 File Delivery；
- 用户要求外部系统写入时，生成草稿不能替代 Connected Delivery；
- Primary Delivery 失败，Execution 不得进入 DELIVERED；
- 同一 Delivery Contract 的重试生成新 Attempt ID；
- 外部系统写入必须绑定 ToolExecutionReceipt。

## 九、Outcome 状态机

Outcome 五个维度分别记录：

```text
Execution
Delivery
Adoption
Business
Learning
```

每个维度状态：

```text
UNKNOWN
PENDING
POSITIVE
NEGATIVE
MIXED
NOT_APPLICABLE
```

Outcome Record 可 revision 更新，但每次更新必须追加 `outcome.observed` Event 和 Observation Receipt。执行成功不能推导 Adoption 或 Business 为 POSITIVE。

## 十、Claim 状态机

### 10.1 Epistemic Status

```text
proposed → asserted
proposed/asserted → derived
asserted → observed
任意有效状态 → disputed
任意有效状态 → superseded
任意有效状态 → expired
```

### 10.2 Confirmation Level

```text
none → direction → option → field
```

两条轴独立：确认级别不会改变 originator，也不会把 `derived` 自动改成 `observed`。

### 10.3 非法转换

- Assistant Recommendation → Human Decision：禁止；
- External Claim → User Preference：禁止；
- Summary → 原始 Human Message：禁止；
- `disputed` → `observed`：需要新 Claim 或显式 Resolution；
- `superseded` 原地恢复：禁止，创建新 Claim。

## 十一、Memory Write Transaction

```text
CANDIDATE
→ EVALUATED
→ APPROVED
→ PENDING
→ COMMITTED
```

分支：

```text
SKIPPED
BLOCKED
CONFLICT
DEFERRED
FAILED
TOMBSTONED
```

- `CONFLICT` 必须重新读取 revision 并执行 Merge Policy；
- 禁止覆盖式重试；
- `DEFERRED` 用于 Memory OS Transport/5xx 或 Outbox；
- 401/403、协议不兼容进入 BLOCKED；
- Tombstone 是新事务，不修改历史 Receipt。

## 十二、Evolution Candidate 与 Rule Authority

### 12.1 Candidate

```text
PROPOSED
→ REVIEWED
→ EVALUATING
→ APPROVED
→ ACTIVE
→ PAUSED
→ RETIRED
```

异常：`REJECTED | QUARANTINED | ROLLED_BACK`。

### 12.2 单活

同一 `assetType + scope + authorityKey` 只允许一个 ACTIVE。激活使用事务锁和 expected active revision。

### 12.3 双仓 Rule 切换

```text
pause old remote
→ activate new remote
→ activate new local
→ retire old local
```

任一步失败，按相反顺序补偿。补偿也通过 Authority Outbox 留痕。

## 十三、统一 Event Envelope

```ts
interface DomainEvent<T> {
  schema: 'awkn-domain-event/v1';
  eventId: string;
  eventType: string;
  eventVersion: number;
  aggregateType: string;
  aggregateId: string;
  aggregateRevision: number;
  executionId: string;
  traceId: string;
  actor: ActorRef;
  idempotencyKey: string;
  receiptIds: string[];
  payloadSchema: string;
  payload: T;
  occurredAt: string;
}
```

### 13.1 命名

```text
<domain>.<entity>.<past-tense-action>
```

示例：

```text
input.envelope.received
input.envelope.trusted
intent.decision.created
goal.spec.frozen
goal.run.started
goal.judgement.completed
context.manifest.created
policy.bundle.compiled
broker.authorization.requested
broker.authorization.granted
tool.execution.started
tool.execution.completed
evidence.cycle.completed
delivery.attempt.completed
outcome.observation.recorded
memory.transaction.committed
evolution.candidate.activated
execution.envelope.closed
```

事件名不得使用含糊词：`done`、`updated`、`handled`、`processed`。

### 13.2 版本与兼容

- Event Type 语义变化时增加 `eventVersion`；
- Payload Schema major 不兼容时 Replay 停止；
- 新字段只能追加为可选字段；
- Consumer 遇到未知可忽略 Event 时必须显式注册 `ignorable=true`；
- 状态投影依赖的 Event 不允许忽略。

## 十四、事务边界

### 14.1 单库事务

以下必须在一个 SQLite 事务：

- Event + Projection + Receipt 关联；
- Authorization 预占/消费；
- Run/Step 状态与 Cycle Receipt；
- Claim 状态与 Claim Event；
- Outbox 记录与本地权威状态；
- Evolve 单活切换。

### 14.2 外部调用

外部模型、工具、Memory OS 调用不得包在 SQLite 长事务中。采用：

```text
短事务写 Intent
→ 事务外调用
→ 短事务写 Completion/Failure
```

### 14.3 Receipt 失败

- 调用前 Intent Receipt 失败：禁止调用；
- 调用后 Completion Receipt 失败：记录本地 Recovery Marker，进入 `SIDE_EFFECT_UNCERTAIN`；
- 非关键 Metric 写入失败：可以 fail-open，但必须记录诊断；
- GoalJudgement、Authorization、ToolExecution、Delivery、MemoryWrite Receipt 属于关键 Receipt。

## 十五、Crash Recovery 与 Replay

启动恢复流程：

```text
检查未完成 Migration
→ 检查 RUNNING/VERIFYING/SENDING
→ 读取最后 Event Revision
→ 验证 Projection Revision
→ 查询外部副作用状态
→ 恢复、补偿、暂停或标记 UNKNOWN
```

规则：

- Event Replay 必须重建相同 Projection Hash；
- 已有成功 Tool Receipt 的幂等动作不得重复；
- 没有 Completion Receipt 的外部写入先查询远端；
- Outbox `SENDING` 超过 lease 后可重新领取；
- Quarantine 记录不得自动重放。

## 十七、测试矩阵

每个状态机必须覆盖：

1. 所有合法转换；
2. 所有非法 from/to；
3. expectedRevision 冲突；
4. 重复 idempotencyKey；
5. Receipt 缺失；
6. 事务中断；
7. Replay 重建；
8. Crash 后外部副作用未知；
9. Pause/Resume；
10. Partial 不升级为整体成功；
11. Goal Judge 假阳性与假阴性；
12. Memory OS Outbox 和补偿。

## 十八、验收

- 所有状态转换由矩阵生成测试；
- `DELIVERED → RUNNING` 被拒绝；
- Tool 成功但验证失败不会产生 Run Success；
- Goal Achieved 必须绑定 GoalJudgementReceipt；
- Receipt 写入失败不会提交关键状态；
- Replay 可重建相同 Projection Hash；
- 重启不会重复不可逆副作用；
- Memory OS 同步失败能区分本地成功、远端待同步和权限阻断。
