## 文章 1：Claude Code 官方教你用 Loop（Feisky）

**核心框架**：Loop 分四层，区分标准是"你愿意交出去什么"。

| 层级 | 交出的东西 | 工具 | 适合场景 |
|------|-----------|------|---------|
| Turn-based | 验证步骤 | Skill | 探索性任务、一次性修改 |
| Goal-based | 停止条件 | /goal | 有明确完成标准的任务 |
| Time-based | 触发时机 | /loop /schedule | 周期性工作、监控外部系统 |
| Proactive | 整个决策流程 | 全部 + 动态工作流 | 长期运行的定型工作流 |

**关键洞察**：
- /goal 的停止条件必须是**确定性的**（数字、测试通过数、分数阈值），描述性结果让大模型自打分不靠谱
- 每次想停下，独立评估模型检查条件是否满足，没满足打回去继续
- /loop 跑在本地，关机停止；/schedule 是云端任务
- Proactive 层最烧 token，动态工作流一次能起几十 agent

**token 控制策略**：
1. 选对原语和模型（90% 任务 turn-based 就够）
2. 确定性工作写脚本（跑脚本比推理便宜）
3. 先小规模试跑
4. 间隔匹配变化频率（PR 一小时一条 review，别 5 分钟轮询）
5. 看消耗明细（/usage /goal /workflows）

## 文章 2：loop/hook/goal 三件套实操（空格的键盘）

**核心观点**：Loop Engineering 对个人落地太难（要搭 6 模块：自动化/worktree/skill/连接器/子agent/状态文件），先把 loop/hook/goal 三件套用好。

### /loop（时间触发）
- 每晚 10 点播客处理流水线
- 凌晨 3 点"省 token 集中跑"（白天额度紧张，凌晨浪费）
- 三层方案：会话内轮询（关窗停）/ 短间隔轮询 / 云端 schedule

### /hook（事件触发）
- AI 腔扫描器：写完 .md 自动 grep 黑名单词典，命中 exit 2 让 Claude 自己改
- commit 前密钥扫描：git diff --cached 扫 sk-/gsk_/AKIA/-----BEGIN/.pem/api_key= 等
- **hook 要短平快**：同步执行，卡住整个 agent 跟着卡；重活留给 Skill 或后台进程

### /goal（目标驱动）
- 任务超 30 分钟、或预感要反复补充需求时才用
- 模板：先写意图不写步骤 → AI 先翻译成 goal → 判断要不要并行 → 主线程保留协调权 → 漂移时显式说明

## 文章 3：Loop 是什么？怎么用？（赛博禅心）

**本质公式**：`while: do cat PROMPT.md | claude; done`

**四种 Loop**（同文章1，略）

**质量保障 4 件事**：
1. 代码库本身要干净（Claude 跟着已有模式走）
2. 给 Claude 自我验证手段（skill 把"好"编码下来）
3. 文档要好拿（最新最佳实践够得着）
4. 用第二个 Agent 做 code review（带新鲜上下文的 reviewer 更客观）

**核心铁律**：循环里必须有能说"不"的东西（测试、类型检查、真实报错）。没有就是 Agent 自己跟自己复读。

## 三篇文章的共识提炼

1. **Loop 不是写提示词，是设计交给 AI 多少自主权**
2. **四层递进**：验证步骤 → 停止条件 → 触发时机 → 整个决策流程
3. **确定性优先**：停止条件、验证步骤尽量用确定性标准（跑测试/分数/数量），不用描述性判断
4. **循环里必须有"说不"的东西**：测试、类型检查、报错、第二 agent review
5. **token 是硬约束**：选对层级、先试水、间隔匹配变化频率、盯用量
6. **hook 短平快，重活给 Skill**：hook 同步阻塞，不能干重活
7. **Skill 是把"好"编码下来**：验证流程、团队规范、最佳实践沉淀成可复用资产
