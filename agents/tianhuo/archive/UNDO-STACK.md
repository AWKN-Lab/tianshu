# 天火可撤销操作栈

> 版本：v1.0
> 来源：Alice 工程方法论"可丢弃组件"原则
> 用途：自进化操作增加撤销能力，防止误改无法回退

---

## 一、可撤销操作定义

### 纳入范围

以下自进化操作必须支持撤销：
- Skill 文件内容修改（awkn-技能治理 / SKILL-AUTOTUNE）
- MEMORY.md 内容修改（经验写回 / 记忆晋升）
- agent.prompt 内容修改（仅限 archive/ 外引用的增量规则）
- 外部引用文件的创建和删除

### 排除范围（不可撤销）

- 已提交的 Git commit
- 已同步到云端的文件
- 已执行的部署操作

---

## 二、快照策略

### 快照时机

操作前必须创建快照：
- Skill 文件修改前
- MEMORY.md 写入前
- agent.prompt 规则变更前

### 快照内容

```yaml
undo-snapshot:
  timestamp: "[ISO8601]"
  operation: "[操作类型]"
  target: "[文件路径]"
  before: "[文件内容或diff摘要]"
  reason: "[操作原因]"
  userConfirmed: true | false
```

### 快照存储

- 路径：`archive/undo-stack/`
- 命名：`[目标文件名]-[timestamp].yaml`
- 保留：最近 20 个快照

---

## 三、撤销执行流程

```
用户要求撤销 → 选择快照
    ↓
读取快照内容
    ↓
对比当前内容（diff）
    ↓
显示变更摘要 + 确认是否继续
    ↓
用户确认 → 执行还原
    ↓
验证还原成功
```

---

## 四、回滚策略按操作类型

| 操作类型 | 撤销方式 | 验证方式 |
|---------|---------|---------|
| Skill 内容修改 | 恢复快照或 git restore | 读取 Skill 文件确认 |
| MEMORY.md 写入 | 删除写入内容（保留格式） | 读取 MEMORY.md 确认 |
| 规则增量修改 | 删除增量部分 | 对比修改前后 diff |
| 新文件创建 | 删除文件 | 确认文件不存在 |

---

## 五、撤销限制

- 只能撤销最近 20 个快照内的操作
- 超出范围的撤销：提示用户手动处理或使用 git
- 已持久化到 Git 的变更：使用 `git revert`

---

## 六、撤销历史展示

当用户询问"能撤销吗"或"撤销历史"时，输出：

```markdown
## 可撤销操作历史

| # | 时间 | 操作 | 目标 | 状态 |
|---|------|------|------|------|
| 1 | 2026-05-28 10:00 | Skill 修改 | awkn-审核 | 可撤销 |
| 2 | 2026-05-28 09:30 | 记忆写入 | MEMORY.md | 可撤销 |
| 3 | 2026-05-27 15:00 | 规则增量 | agent.prompt | 已超期 |

最近快照：`archive/undo-stack/awkn-审核-20260528T100000.yaml`
```

---

## 七、与 SKILL-AUTOTUNE 集成

SKILL-AUTOTUNE 中的版本备份即为本栈的快照实现：
- 备份路径：`archive/skill-backups/[技能名]-[日期]-[时间].md`
- 回滚：复制备份内容回 Skill 文件
- 区别：SKILL-AUTOTUNE 备份保留历史版本，本栈记录最近 20 个操作
