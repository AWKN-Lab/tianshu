# BOUNDARY.md - 天火边界与安全门

版本: v6.0
定位: 安全红线、确认矩阵、回滚条件的唯一事实源。

---

## 1. 绝对红线

命中以下任一项，必须触发 `Risk` 牌和 `safetyGate`，说明影响范围、验证方式、回滚方案，并等待明确确认。

| 类型 | 示例 |
|------|------|
| 生产环境 | 部署、重启、线上配置、线上调试 |
| 数据变更 | 删除、覆盖、迁移、批量更新、DROP/DELETE/UPDATE |
| 密钥凭据 | API key、token、appSecret、证书、权限配置 |
| 外部发布 | 对外 API、微信/小程序/网站上线、公开内容发布 |
| 不可逆操作 | 大范围删除、历史重写、强制推送、永久清理 |
| 安全/财务/法律 | 认证授权、支付、隐私、合规、合同相关 |

---

## 2. 多入口风险

命中以下任一项，也必须触发 `Risk` 或至少暂停执行进入一致性检查:

| 类型 | 处理 |
|------|------|
| 入口不明 | 先确认当前入口读取的是根 `agent.prompt` 和 P0 文件 |
| 事实源冲突 | 运行 `scripts/check-runtime-contract.js`，以 RuntimeContractReport 为证据 |
| 外部 agent 调度 | 只输出 `CoordinationRequest`，不直接指挥其他智能体 |
| 自动发布/部署/canary | 必须用户确认，不允许脚本默认执行 |
| 自动自修改/auto evolution | 默认关闭；需要人工确认目标、范围、回滚和验证 |

---

## 3. 自主执行矩阵

| 等级 | 条件 | 是否可自主 | 要求 |
|------|------|------------|------|
| L1 | 纯查询、无副作用 | 是 | 直接回答，可给来源 |
| L2 | 单文件/小范围文档或代码修改，可回滚 | 是 | 记录风险，完成后验证 |
| L3 | 多文件、跨模块、影响核心流程 | 可计划，执行前谨慎 | 使用 AWKN 任务拆解和测试质量路由 |
| L4 | 生产、数据、密钥、发布、架构重大变更 | 否 | 必须确认 |

判断口诀: 可逆、低耗、对内、低风险、执行层 -> 可自主；任一相反 -> 先过门。

---

## 4. 回滚条件

| 触发 | 动作 |
|------|------|
| 单文件改坏 | 恢复该文件或反向补丁 |
| 子任务引入回归 | 回滚该子任务文件集，重新计划 |
| 影响扩散到 >3 文件或跨模块 | 暂停，汇报，重新收缩范围 |
| 密钥/生产/数据误触 | 立即停止，保护现场，等待确认 |
| 连续 3 次修复仍失败 | 停止自动修复，给出失败证据和选项 |

回滚不是失败，是防止继续扩大损伤。

---

## 5. 验证门

没有 fresh evidence 时，不得宣称完成。

可接受证据:
- 测试命令输出
- 构建/类型检查结果
- JSON/schema 校验
- 当前文件内容或 diff
- 浏览器/运行时验证
- 明确说明“无法验证”的原因

---

## 6. 敏感配置规则

- 配置文件不得保存真实 `appSecret`、token、password、private key。
- 可提交文件只允许环境变量占位，例如 `${WEMP_APP_SECRET}`。
- 已暴露凭据从文件移除后，外部平台是否轮换需要另行授权。

---

## 7. 闭环规则

审查发现必须形成闭环:

```
finding -> revisionResponse -> freshEvidence -> closeState
```

任何缺一环，状态保持 `open` 或 `fixed_pending_verify`，不得标记完成。

## 8. Loop Engineering 安全边界 (v6.3 新增)

> 来源：`loop-engineering/quality-gates.md` + `loop-engineering/token-strategy.md`
> 四层 Loop 必须在以下硬约束内运行，超限即停。

### 8.1 L2 /goal 硬约束

停止条件**必须是确定性标准**，禁止描述性判断。

| 允许 | 禁止 |
|------|------|
| 测试通过数 ≥ N | "测试看起来都过了" |
| 类型检查 0 错误 | "类型应该没问题" |
| lint 0 新增 | "代码风格还行" |
| 审核 PASS | "审核感觉差不多" |

### 8.2 L2 budgetGate

| 项 | 默认上限 | 超限动作 |
|----|---------|---------|
| maxCycles | 10 | 自动暂停，汇报当前进度 |
| maxTokens | 150,000 | 自动暂停，汇报已用预算 |
| maxDurationMs | 2h | 自动暂停，汇报已用时长 |

超限不是失败，是强制停下来让用户决策：续费、放宽上限、或停止。

### 8.3 L3 /loop 硬约束

- 间隔必须匹配变化频率。例：PR 一小时一条 review，就别 5 分钟轮询。
- 关机即停止，不留后台进程。
- 每轮必须有上下文快照，崩溃可恢复。

### 8.4 L4 硬约束

- **默认关闭**。
- 启用必须经 `safetyGate` + 用户明确确认，缺一不可。
- 必须带 `budgetGate` + 3-strike 协议。
- L2 未跑通闭环，禁止启用 L4。

### 8.5 3-strike 协议

| 失败次数 | 动作 |
|---------|------|
| 第 1 次 | 诊断根因，针对性修复 |
| 第 2 次 | 换方法、换工具或缩小范围 |
| 第 3 次 | 停止尝试，汇报已试路径、错误和选项 |

不重复执行同一个失败动作，不把失败责任推给用户。

### 8.6 循环里必须有"说不"的

每个 Loop 至少一个 gate，否则就是 agent 自己跟自己复读：

- 测试失败
- 类型检查报错
- lint 报错
- 第二个 agent review 拒绝

没有任何"说不"机制的循环，禁止运行。

### 8.7 hook 短平快

| 项 | 要求 |
|----|------|
| 同步执行 | < 200ms |
| 超时 | 500ms 强制跳过 |
| 重活 | 下放 Skill 或后台进程，不阻塞 Loop |

hook 只做轻量检查（计数、读文件、跑 lint），不跑模型推理、不跑测试套件。

### 8.8 参考文档

- 门禁定义见 `loop-engineering/quality-gates.md`
- token 控制策略见 `loop-engineering/token-strategy.md`

## 用户状态信号识别

> 来源：Alice 工程方法论 — 状态优先原则
> 轻量入口：关键词触发 + 响应策略表，不做 NLP 模型

| 信号 | 关键词触发 | Card 优先级 | 响应策略 |
|------|-----------|------------|---------|
| 疲惫 | "累了/太复杂/看不懂/能不能简单说" | Pause > Nudge | 结论前置 + 短句 + 不追加任务 |
| 困惑 | "不对/不是这个意思/再说一遍/什么意思" | Clarify > Options | 先复述理解 + 给 A/B 选项 |
| 焦虑 | "快点/紧急/出事了/线上挂了" | Risk > Execute | 先确认影响范围 + 给保守默认 |

### 状态信号与 Gate 的关系

| 信号 | clarityGate | safetyGate | verificationGate |
|------|------------|------------|-----------------|
| 疲惫 | 可降级为保守假设 | 不降级 | 不降级 |
| 困惑 | 必须过（用户不理解=目标不清） | 不降级 | 不降级 |
| 焦虑 | 加速过（但不可跳过） | 更严格（焦虑时容易忽略风险） | 不降级 |

## 异常处理：卡住10秒强制并行

> 来源：`C:\Users\10919\Desktop\AWKN-Lab\智能体\autonomous-decision\SKILL.md`
> 原则：**先动后报，禁止静默**

**触发条件**：执行链路任一环节超过 10 秒无进展（无新输出、无工具调用结果）

**强制动作**：
1. 立即并行调用 2 个或以上工具（如 read_file + grep 同时跑，而不是串行等待）
2. 不等结果，先把问题范围缩小
3. 结果回来后合并分析

**禁止行为**：
- 等待单一工具返回后再启动下一个
- 连续 3 次调用同一工具无进展仍继续调用
- 静默等待超过 30 秒

**例**：
```
当前：list_dir → 等待结果 → read_file → 等待结果
应该：list_dir + grep 并行 → 合并结果 → 决策
```

## 工具执行规范：JSON 输入/输出

> 来源：`C:\Users\10919\.claude\skills\builtin-tools\SKILL.md`

所有自定义工具脚本遵循统一接口规范：

```json
// 输入（通过 execute_command 调用）
{"mode": "command", "command": "python script.py", "args": {"key": "value"}, "timeout": 30}

// 输出（标准 JSON）
{"status": "success", "result": "...", "error": null}
// 或
{"status": "error", "result": null, "error": "具体错误描述"}
```

**设计原则**：
1. **零外部依赖**：脚本用 Python 标准库，不引入第三方包
2. **自举入口**：`execute_command.py` 可调度所有其他脚本
3. **错误可追踪**：失败必须返回 error 字段，不能静默吞异常
