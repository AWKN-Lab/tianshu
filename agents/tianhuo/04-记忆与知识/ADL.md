## 📉 劣化检测

### 自动化检测脚本

```javascript
// scripts/check-devolution.js

const metrics = {
  decisionAccuracy: getDecisionAccuracy(), // 决策准确率
  reworkRate: getReworkRate(),             // 返工率
  responseTime: getResponseTime(),         // 响应时间
  testCoverage: getTestCoverage()          // 测试覆盖率
};

// 检测劣化
const degradation = {
  accuracy: metrics.decisionAccuracy < 0.9,  // <90% 触发
  rework: metrics.reworkRate > 0.2,          // >20% 触发
  response: metrics.responseTime > 300,      // >5 分钟触发
  coverage: metrics.testCoverage < 0.8       // <80% 触发
};

// 如果任一指标劣化，触发告警
if (Object.values(degradation).some(d => d)) {
  console.error('⚠️ 检测到劣化信号:', degradation);
  triggerRollback();
}

function triggerRollback() {
  // 1. 获取上一个稳定版本
  const lastStableTag = getLastStableTag();
  
  // 2. 回滚到该版本
  console.log(`🔄 回滚到版本：${lastStableTag}`);
  executeRollback(lastStableTag);
  
  // 3. 通知管理员
  notifyAdmin('检测到劣化，已自动回滚');
}
```

## 🔄 回滚流程

### 回滚触发条件

**自动触发**:
1. 决策准确率下降>10%
2. 返工率>20%
3. 用户投诉>3 次/周
4. 测试覆盖率<80%

**手动触发**:
1. 管理员发现异常
2. 智能体自检发现劣化
3. 用户反馈问题严重

---

### 回滚步骤

```
1. 检测劣化信号
   ↓
2. 确认劣化 (对比历史数据)
   ↓
3. 获取上一个稳定版本 (git tag)
   ↓
4. 执行回滚 (git checkout)
   ↓
5. 验证回滚效果
   ↓
6. 通知管理员
   ↓
7. 记录回滚日志
```

---

### 回滚命令

```bash
# 查看版本历史

# 回滚到指定版本

git checkout v1.0.0-20260307 -- agents/tianhuo/AGENTS.md
```

## 🔔 告警机制

### 告警级别

**一级告警 (严重)**:
- 触发条件：任一核心指标触及回滚阈值
- 响应：立即自动回滚 + 通知管理员
- 示例：决策准确率从 95% 降至 85%

**二级告警 (警告)**:
- 触发条件：指标连续 3 天下降
- 响应：通知管理员 + 记录日志
- 示例：响应时间从 1 分钟 → 2 分钟 → 3 分钟

**三级告警 (注意)**:
- 触发条件：单次指标异常
- 响应：记录日志 + 持续观察
- 示例：某天返工率 15% (正常 10%)

## 2026-04-25 凌扬健身项目学到的规则

### 规则1：前后端必须同时审计

改前端代码时，必须同步检查后端 handler：
- 检查异常处理（try-catch）是否完整
- 检查数据库连接管理（pool.query vs getConnection+release）
- 检查事务边界（begin/rollback/commit）
- 问自己：这个 API 异常时会发生什么？

**案例**：backend.js 的 POST /api/member/info 缺少 try-catch（GET 版本有），异常时服务器崩溃

### 规则2：验证必须独立

说"已清理"之后，必须用 grep 实际验证，不能凭记忆判断。

**案例**：setTimeout 伪默认值藏在 plan-result.js，不在 plan.js。说"已清理"后 grep 发现它还在

### 规则3："跑通了"不等于"正确"

要检查：异常输入、失败情况、资源泄漏、超时处理。

**案例**：GPT 说"连接池泄漏"是误判 — backend.js 用 pool.query 不需要手动 release，但确实缺少 try-catch

### 规则4：交叉验证

在 A 模块发现的问题，要 grep 检查 B 模块是否有相同问题。

**验证命令**：
```bash
# 检查后端 handler 是否有 try-catch
grep -n "app\.(post|get)\('/api/" backend.js | head -20

# 检查 setTimeout 遗留
grep -rn "setTimeout" pages/

# 检查硬编码 localhost
grep -rn "127\.0\.0\.1\|localhost" backend.js
```
