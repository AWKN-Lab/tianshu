## 2. 根因分析

### Bug 1 (M3 进阶-24)：execTool 命令失败返回字符串 — high

**代码**：
```typescript
catch (err) {
  const e = err as Error & { stdout?: string; stderr?: string };
  return `[error] ${(e.stderr ?? '') + (e.stdout ?? '')}`.slice(0, 50000);
}
```

**问题**：catch 块返回 `[error]` 字符串而非 throw。
- agent-loop（line 276-296）：`isError = false`（没抛错）→ consecutiveErrors 不增 → 3-strike 不触发
- recordLoopFailure 不被调用 → corrections-ledger 收不到工具失败证据 → 自进化闭环对工具错误盲区
- ENOENT（命令不存在）时 stderr/stdout 为空 → 返回 `[error] `（近空串）→ 无信号被当作成功
- 与 M3 进阶-7 skillTool terminated 修复不一致（terminated 已改为 throw，但参数校验/skill not found 仍返回字符串）

**影响链**：工具失败 → 返回字符串 → agent-loop 视为成功 → consecutiveErrors=0 → 3-strike 不触发 → recordLoopFailure 不调 → corrections-ledger 空 → pattern-detector 盲区 → experience-writer 不生成工具错误经验 → 自进化闭环断链

catch (err) {

## 5. 候选铁律

### E99：工具执行失败必须 throw，不能返回错误字符串

**适用情境**：ToolHandler.execute 的所有错误路径（参数校验失败、资源不存在、命令执行失败、子循环 terminated）。

**铁律**：工具执行失败必须 throw，不能返回 `[error]` / `File not found` 等错误字符串。返回字符串会被 agent-loop 视为成功（isError=false），绕过 consecutiveErrors / 3-strike / recordLoopFailure，导致：
1. 3-strike 不触发（连续工具失败不终止循环）
2. recordLoopFailure 不调（corrections-ledger 收不到工具失败证据）
3. 自进化闭环对工具错误盲区（pattern-detector 无数据）

**反例**：
```typescript
catch (err) {
  return `[error] ${stderr + stdout}`; // 假成功 — agent-loop 视为成功
}
```

**正例**：
```typescript
catch (err) {
  throw new Error(enrichedMessage); // agent-loop catch 记录 isError + recordLoopFailure
}
```

**与 E96 的关系**：E96 是 provider 层接收外部输入的 fail-closed（空 content）；E99 是工具层执行失败的 fail-closed（throw 而非返回字符串）。两者互补 — 都是为了让错误"可见"于确定性追踪机制。

**LLM 可见性不变**：throw 后 agent-loop line 310 格式化为 `[error] ${errorMessage}` 传给 LLM，LLM 仍能看到错误内容并推理。throw 只是打开了"错误追踪"通道（isError + consecutiveErrors + recordLoopFailure），不改变 LLM 可见性。
