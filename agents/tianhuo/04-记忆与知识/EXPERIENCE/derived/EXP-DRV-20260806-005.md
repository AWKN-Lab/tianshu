# EXP-DRV-20260806-005｜PG 库备份/归档：凭据与权限坑——应用代码的 DB_URL 是最可靠的钥匙，双向 SHA256 是删除前的保险

## 教训

2026-08-06 归档 hindsight 3.2G 库时连踩两个认证/权限坑，各耗 10 分钟：

- 坑 1：`pg_dump -U hindsight` 无 PGPASSWORD → 卡在 `Password:` 交互提示 10 分钟超时（非交互 SSH 下不可见）
- 坑 2：`su postgres -c "pg_dump -h 127.0.0.1 ..."` 走 TCP 需要密码认证失败 + postgres 用户写 /tmp 权限不足
- 解法：从应用代码 `start.py` 的 `DB_URL=postgresql://hindsight:hindsight2026@127.0.0.1:5432/hindsight` 取密码 → `PGPASSWORD=hindsight2026 pg_dump -U hindsight -h 127.0.0.1 -d hindsight -Fc -f /tmp/...` 一次成功（198M，3.2G 库压缩率 94%）
- 收尾：scp 本地 → `Get-FileHash` 与服务器 `sha256sum` 完全一致 → 才执行停服删库

- 证据 1：0 字节 dump 文件 + 10 分钟超时（第一次交互卡死）
- 证据 2：`su postgres` 报 "could not change directory to /root: Permission denied" + 输出文件 Permission denied
- 证据 3：PGPASSWORD 方案 16:58 一次成功，dump 198M，双方 SHA256 = 5b948a9b…

## 验收

- pg_dump 前先读应用代码 DB_URL 取用户/密码/端口，用 PGPASSWORD 非交互执行
- 写 /tmp 失败时改用 root 用户 + PGPASSWORD（而非 su postgres）
- 任何删库/删表前：dump 落地本地 + 服务器与本地 SHA256 双向一致 + 恢复可行性备注
- 非交互 SSH 命令一律防交互（`< /dev/null` 或 PGPASSWORD/expect），杜绝隐形卡死
