# EXP-DRV-20260806-005｜PostgreSQL 备份归档：凭据取自权威配置，删除前必须完成恢复校验

## 适用范围

PostgreSQL 数据库备份、迁移、归档和删库操作。

## 教训

非交互环境执行 `pg_dump` 时，凭据猜测、交互式密码提示和用户切换都可能造成超时或权限失败。可靠路径是读取应用的权威配置来源，通过受控环境变量注入凭据，生成 dump 后执行本地落盘、哈希一致性检查和恢复可读性验证。

- 证据 1：未提供非交互凭据时，`pg_dump` 停在密码提示并超时。
- 证据 2：切换数据库系统用户后，TCP 认证和输出目录权限仍可能失败。
- 证据 3：使用应用配置中的连接信息，以非交互方式执行后备份成功；服务器与本地文件哈希一致。

## 安全边界

- 禁止把真实 `DB_URL`、密码、Token、完整连接串或私钥写入经验文件、日志和 Git。
- 凭据只能在运行时从受控配置或秘密管理器读取。
- 本事件中曾出现的明文凭据应视为已暴露，需在对应系统轮换；本候选不保存原值。

## 反例

```text
错误：在命令、报告或经验文件中写出完整连接串和密码。
错误：只验证 dump 文件存在或哈希一致，就直接删库。
正确：权威配置读取凭据 → 非交互 dump → 本地落盘 → 哈希一致 → pg_restore --list/隔离恢复演练 → 才允许删除。
```

## 触发词

pg_dump / PostgreSQL 备份 / 删库 / 数据库归档 / PGPASSWORD / 密码提示超时 / 权限失败 / 数据库迁移

## 验收

- 凭据不出现在命令回显、报告、经验文件和 Git 历史中。
- dump 在服务器和本地均存在，完整性校验一致。
- 至少执行 `pg_restore --list`；高风险删除需完成隔离库恢复演练。
- 删除前保存操作回执、备份位置代号和恢复验证结论。

## 失效条件

当数据库备份完全迁移到托管快照、集中秘密管理和自动恢复演练平台后，本经验可合并进平台级灾备规范。
