# EXP-DRV-20260806-004｜静默降级 = 故障隐形：集成失败必须显式（日志/告警），比静默回退好一万倍

**状态**: DRAFT
**类型**: DERIVED
**适用范围**: 任何系统集成/服务间调用/回退设计场景（AI 服务降级关键词搜索、缓存回退、API 超时兜底等）
**关联 commit**: 无

## 教训

hatwin（程掌柜）的 hindsight 知识检索集成因三重错位从未连通，但 retriever 的设计是"超时→返回空→回退关键词搜索"，业务路径始终"正常"。结果：一个 3.2G 的孤儿系统无人发现、无人处置，静默运行 55 天。故障不是没有发生，而是被降级设计消化成了"看不见"。

- 证据 1：`hindsight-retriever.js` 对 hindsight 调用失败返回空结果，调用方走关键词回退，无错误日志/告警
- 证据 2：55 天无人发现（最后摄入 06-17，consolidation 06-12 停摆，37,802 待整合无告警）
- 证据 3：直到人工盘点 + 用户纠正方向才暴露——监控/日志完全缺席

## 反例

```text
错误：集成失败 → 静默回退 → 业务"正常" → 没人知道集成早就断了
正确：集成失败 → 显式日志（warn/error）+ 首失败告警 + 降级标记 → 有人知道 → 及时修复或摘除
```

## 触发词

静默降级 / 连接失败 / 回退 / 超时兜底 / 集成断了没人发现 / 服务不可用 / 告警 / 监控盲区

## 验收

- 新增任何"调用外部服务失败后回退"的逻辑，必须同时写显式日志（至少 warn 级 + 降级来源标识）
- 对关键集成（知识检索、LLM、支付等）要有连接健康检查或失败计数告警
- 修复类任务发现"降级掩盖故障"时，除修复连接外必须补上日志/告警缺口
