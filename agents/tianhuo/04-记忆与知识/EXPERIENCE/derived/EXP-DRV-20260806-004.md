# EXP-DRV-20260806-004｜静默降级会隐藏集成故障：回退必须可观测

## 适用范围

外部服务调用、知识检索、缓存回退、API 超时和功能降级设计。

## 教训

调用失败后返回空结果并继续执行，可以维持表面可用性，却会把长期断连伪装成正常业务。关键集成的降级必须携带来源标识、失败计数和健康状态，并在持续失败时产生告警。

## 反例

```text
错误：集成失败 → 返回空结果 → 静默走本地回退。
正确：集成失败 → 记录结构化错误和降级状态 → 执行受控回退 → 达到阈值后告警。
```

## 安全边界

- 日志必须脱敏，不记录凭据、完整连接串或用户敏感数据。
- 告警不得暴露内部基础设施细节。

## 验收

- 每次降级都有可查询事件和明确来源。
- 提供首次失败、连续失败和恢复通知。
- 监控可以区分主链路成功、降级成功和完全失败。

## 失效条件

当平台统一提供熔断、降级标记和告警能力后，本经验可并入平台可靠性规范。
