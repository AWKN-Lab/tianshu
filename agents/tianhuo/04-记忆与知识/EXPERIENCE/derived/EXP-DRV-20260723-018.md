## 2. 根因分析

### Bug 1（M3 进阶-27-A）：recordObservation 返回值不接住 — critical

**原代码**（agent-loop.ts line 290）：
```typescript
recordObservation(reactState, {
  toolName, args, result: toolResult,
  isError, errorMessage, durationMs,
});
```

**问题**：`recordObservation` 是纯函数（返回新 ReActState，不 mutate）。原版不接 return → reactState 永远不更新：
- `reactState.observations` 永远是 `[]`（初始空数组）
- `reactState.totalObservations` 永远是 `0`
- `reactState.consecutiveErrors` 永远是 `0`
- `reactState.totalErrors` 永远是 `0`

**影响链**：recordObservation 不更新 state → consecutiveErrors=0 → shouldReflect 永远返回 false（条件 `consecutiveErrors >= 1` 不满足）→ reflect 永不触发 → 反思机制完全死代码。即使工具连续失败 100 次，反思也不会触发 —— "假完成"模式的极端形态。

### Bug 2（M3 进阶-27-B）：reflect 返回值不接住 — critical

**原代码**（agent-loop.ts line 327）：
```typescript
if (shouldReflect(reactState)) {
  reflect(reactState);
  if (reactState.lastReflection && !reactState.lastReflection.shouldContinue) {
    // ...
  }
}
```

**问题**：`reflect` 是纯函数，返回新 state。不接 return → `reactState.lastReflection` 永远是 undefined → 下面的 `if (reactState.lastReflection && ...)` 永远是 false → reflection stop 永远不触发。

**双重死代码**：即使 Bug 1 修复了（shouldReflect 能返回 true），Bug 2 仍会让 reflection stop 失效。

### Bug 3（M3 进阶-27-C）：recordTokenUsage 返回值不接住 — high

**原代码**（agent-loop.ts line 234）：
```typescript

```

**问题**：`recordTokenUsage` 返回 boolean（是否检测到异常）。原版不接 return → 异常被检测 + logged → 但循环不停止 → "假检测"。

**对比**：同文件的 `recordFailure`（line 220）和 `recordToolCall`（line 314）都接住返回值并据此终止循环。`recordTokenUsage` 不接是 inconsistency。

### Bug 4（M3 进阶-27-D）：recordTokenUsage 不验证 NaN/负数 — high

**原代码**（loop-monitor.ts）：
```typescript
recordTokenUsage(tokens: number): boolean {
  this.tokenHistory.push(tokens);
  // ...
  if (recent[0] > 0 && recent[2] / recent[0] > this.config.maxTokenGrowth) {
    return true;
  }
  return false;
}
```

**问题**：tokens 为 NaN 时，`NaN > 0` = false → 跳过 anomaly 检查 → 返回 false（无异常）。NaN 被静默 push 到 tokenHistory，污染后续判断。

**修复**：在 push 之前用 `Number.isFinite(tokens) && tokens >= 0` 验证，无效输入直接返回 true（anomaly）。

## 5. 候选铁律

### E101：纯函数的返回值必须被调用方接住并使用

**适用情境**：所有纯函数（返回新 state / 返回 boolean / 返回计算结果，不 mutate 输入）的调用点。

**铁律**：纯函数的返回值必须被调用方接住并使用（赋值给变量、作为条件、传给下一函数）。丢弃纯函数返回值等于白调用 —— 函数执行了（消耗 CPU）但其效果完全丢失。这比"假完成"更严重：代码看起来在做事，实际什么都不做，且因为函数确实运行了（不是死代码），更难被静态分析或测试发现。

**反例**：
```typescript
recordObservation(reactState, { ... });  // ← 纯函数返回值被丢弃，reactState 不更新
reflect(reactState);                     // ← 纯函数返回值被丢弃，lastReflection 永远 undefined
this.loopMonitor.recordTokenUsage(...);  // ← 返回 boolean 被丢弃，异常不终止循环
```

**正例**：
```typescript
reactState = recordObservation(reactState, { ... });  // ← 接住返回值
reactState = reflect(reactState);                     // ← 接住返回值
const anomaly = this.loopMonitor.recordTokenUsage(...);
if (anomaly) { /* terminate */ }                     // ← 接住并使用
```

**与 E100 的关系**：E100 是注释与代码不一致；E101 是调用方与函数契约不一致（函数声明返回值，调用方却丢弃）。两者都是"声明 vs 行为"不一致的变体。

**检测方法**：
1. 静态：grep 所有 `xxxFunction(args)` 不含 `=` 的调用（排除 void 返回类型）
2. 动态：单元测试断言函数调用后 state 确实更新
3. 代码审查：关注 `const xxx = ...` 后续调用纯函数是否需要改 `let`

### E102：数值输入必须验证有限性（NaN/Infinity/负数）

**适用情境**：所有接收数值输入的安全/检测函数（异常检测、预算计算、阈值判断等）。

**铁律**：接收数值输入的函数必须用 `Number.isFinite(x) && x >= 0`（或适当的下界）验证，无效输入应 fail-closed（视为异常 / throw），不污染内部状态。NaN 与任何数比较都返回 false（`NaN > 0` = false, `NaN < 0` = false），会静默跳过所有阈值检查 —— "无信号被当作成功"的经典入口。

**反例**：
```typescript
recordTokenUsage(tokens: number): boolean {
  this.tokenHistory.push(tokens);  // ← NaN 直接进入历史
  if (recent[0] > 0 && recent[2] / recent[0] > threshold) {  // ← NaN > 0 = false，跳过
    return true;
  }
  return false;  // ← NaN 静默通过
}
```

**正例**：
```typescript
recordTokenUsage(tokens: number): boolean {
  if (!Number.isFinite(tokens) || tokens < 0) {
    return true;  // ← fail-closed，视为 anomaly
  }
  this.tokenHistory.push(tokens);
  // ...
}
```

**与 E96 的关系**：E96 是 LLM provider 接收外部输入的 fail-closed（空 content）；E102 是数值计算函数接收输入的 fail-closed（NaN/Infinity/负数）。同属"无信号被当作成功"防御。
