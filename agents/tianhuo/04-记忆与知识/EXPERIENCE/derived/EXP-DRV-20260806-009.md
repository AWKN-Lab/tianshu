# EXP-DRV-20260806-009｜命令模板必须匹配项目契约，禁止把不存在的工具当成门禁

## 来源证据

Runtime 告警中出现 `eslint` 不可执行，但目标 Runtime 的 `lint` 脚本实际调用架构扫描器；另一些项目使用 Biome。通用模板直接执行 `eslint` 会制造与项目真实契约无关的失败。

## 教训

门禁执行器必须读取目标项目的脚本声明和锁文件，再决定执行命令。命令名称相同不代表实现相同，工具生态也不能靠模板猜测。优先执行项目公开脚本，如 `npm run lint`、`npm run typecheck`、`npm test`，避免直接调用底层工具。

## 反例

```text
错误：所有 JavaScript 项目统一执行 eslint、tsc、jest。
正确：读取 package.json scripts → 验证脚本存在 → 通过包管理器执行公开契约 → 保存退出码和工具版本。
```

## 工程规则

- 门禁命令来自项目声明，不来自全局模板硬编码。
- 缺少脚本时返回 `SCRIPT_NOT_DECLARED`，不得自动换成猜测工具。
- 允许项目明确声明等价命令映射，但必须版本化和可审计。
- 执行回执记录工作目录、脚本名、实际展开命令和退出码。

## 验证

- 在使用架构扫描器、Biome 和 ESLint 的三个夹具项目中，执行器分别调用各自脚本。
- 项目未声明 `lint` 时返回结构化缺口，不尝试执行全局 eslint。
- clean checkout 与本机执行结果一致。

## 授权边界

只读取项目脚本并执行已声明的只读门禁；不得自动安装工具、修改 package.json 或替换项目技术栈。

## 失效条件

当所有项目采用统一的声明式门禁清单并由 Runtime 原生解析后，本经验可并入门禁契约规范。
