# EXP-DRV-20260805-009｜runtime 改动时的 agents 档检查远程兜底盲区

**状态**: DRAFT
**类型**: DERIVED
**适用范围**: 远程 CI workflow 设计（runtime-ci.yml / agents-ci.yml 各自的 paths 与 jobs 平衡）
**关联事件**: 2026-08-05 上一轮 finding 修复（commit 4944ef0）后复盘报告 §6 待确认信息第 2 条——"agents-ci.yml 的 paths 是否要包含 runtime/**"实际错位，真问题是 runtime-ci.yml 在 runtime 改动时不跑 agents 档检查

## 教训

**"档位继承对齐"必须双向闭环**：本地三档门禁是 `agents ⊆ contract ⊆ full`，所以 runtime 改动本地落 full 档会跑 agents 检查（full ⊇ contract ⊇ agents）。但远程 CI 是按 path 触发独立 workflow，**没有继承语义**——runtime-ci.yml 触发时不跑 agents 档，agents-ci.yml 触发时不跑 runtime 档。这是设计层面的"档位语义 vs 远程触发语义不对齐"。

**真实盲区**：runtime 改动可能影响 agents/ 下资产（structured-assets / markdown-assets / core-code boundary）——例如：
- `runtime/src/evolve/*` 改完后，EXPERIENCE/reports/ 下 EXP-DRV 文件状态变化（如 DRAFT → 已起草根因），agents 档的 markdown 资产校验会发现 unindexed EXP
- `runtime/src/llm/router.ts` 改完后，runtime/contract 与 agents/tianhuo/scripts/check-runtime-contract.js 引用的契约可能不对齐

但远程 runtime-ci.yml 触发时只跑 light-check（typecheck）+ ocr-producer + check（runtime checks + build），**agents 档被绕过**。本地 full 档会抓到（contract ⊇ agents），但远程裸奔。

**修复策略**：在 runtime-ci.yml 末尾新增 `agents-check-on-runtime-change` job，复用 agents-ci.yml 的同一组 check-*.js step（与三档唯一真源语义一致）。

**已知次级问题**：check-runtime-contract.js 依赖 `skills/awkn-程序员天阶功法/hooks/handoff-schema.json`，该文件为项目级缺失（hooks 目录都不存在，文件从未 commit），导致 check-runtime-contract.js 一直 exit 1。新 job **暂不含该 step**，等天阶功法作者补全 schema 后再扩展。
