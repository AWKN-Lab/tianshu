## 2. 根因分析

### Bug 1 (M3 进阶-19)：hook 返回空 content 假成功 — critical

**代码**：
```typescript
for (const r of results) {
  if (r.success && r.llmResponse) {
    return { content: r.llmResponse.content, ... finishReason: 'stop' };
  }
}
```

**问题**：只检查 `r.success && r.llmResponse`，不检查 `content` 是否为空。
- hook 实现有 bug 返回 `{ success: true, llmResponse: { content: '' } }` 时
- trae 不 throw → router 不 fallback → agent-loop 收到空 content
- 3-strike 不触发（没抛错）→ 循环空转
- usage=0 → budgetGate 不触发（token 不增长）
- 与历史 trae.ts stub bug（返回 fake success）同类

**影响链**：空 content → 无输出 → 无错误 → 无 fallback → 无 budget 消耗 → 循环永久空转

### Bug 2 (M3 进阶-20)：fileBridge 资源泄漏 — medium

**代码**：4 个出口分别用 `unlinkSync(reqPath)` / `unlinkSync(respPath)` 清理
- 成功解析：删 req + resp ✓
- 换行修复后成功：删 req + resp ✓
- JSON.parse 失败：只删 resp（req 残留）✗
- timeout：只删 req（resp 若刚出现会泄漏）✗

**根因**：多出口资源清理没有统一到单一函数，每个出口手动清理，容易遗漏。

### Bug 3 (M3 进阶-21)：parseDependencies 正则 CRLF 不一致 — medium

**代码**：
- parseSkillFile L22：`/^---\r?\n([\s\S]*?)\r?\n---/`（支持 CRLF）
- parseDependencies L181：`/^---\n([\s\S]*?)\n---/`（只支持 LF）

**问题**：同模块两套正则，一套支持 CRLF 一套不支持。
- CRLF 行尾的 SKILL.md 在 parseSkillFile 中正常解析（name/version 等）
- 但 parseDependencies 中匹配失败 → dependencies 静默丢失
- 调用方无法发现依赖丢失（返回空数组而非报错）

## 5. 候选铁律

### E96：外部输入校验必须 fail-closed（provider 层）

**适用情境**：provider / 适配器 / 桥接层接收外部输入（hook 返回、文件桥接响应、API 响应）时。

**铁律**：接收外部输入的接口必须校验"有效载荷非空性"。空 content / 空 choices / 空响应不能当作成功返回，必须 throw 或跳过让 fallback 链生效。

**反例**：`if (r.success && r.llmResponse) return { content: r.llmResponse.content }` — 不检查 content 是否为空。

**正例**：`if (r.success && r.llmResponse) { const content = r.llmResponse.content ?? ''; if (content.trim() === '') continue; return { content }; }`

**与 E94 的关系**：E94 是 hook 本身的 fail-closed（hook 输出非 JSON 时）；E96 是 provider 层对接收数据的 fail-closed（数据为空时）。两者互补。

### E97：资源清理统一到单一出口函数

**适用情境**：函数有多个 return / throw / 异常出口，且每个出口需要清理相同资源。

**铁律**：多出口的资源清理必须统一到一个 cleanup 函数，所有出口调用它。禁止在每个出口手动清理（容易遗漏）。

**反例**：
```typescript
// 出口 A
try { unlinkSync(reqPath); } catch {}
try { unlinkSync(respPath); } catch {}
return result;
// 出口 B
try { unlinkSync(respPath); } catch {} // 忘了 reqPath
return null;
```

**正例**：
```typescript
const cleanup = () => { try { unlinkSync(reqPath); } catch {} try { unlinkSync(respPath); } catch {} };
// 出口 A
cleanup();
return result;
// 出口 B
cleanup();
return null;
```
