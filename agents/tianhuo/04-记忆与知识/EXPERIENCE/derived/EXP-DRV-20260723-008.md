# EXP-DRV-20260723-008 — skill-tool 不检查 terminated（子循环失败当成功 + 跨循环 terminated 传播）

- **类型**: derived（推导经验，人工沉淀）
- **日期**: 2026-07-23
- **触发**: 用户要求"实现完整的自主、自动、自进化的闭环 /goal" — 审查 tools/builtin/skill-tool.ts 时发现不检查 result.terminated
- **作者**: AI + 用户监督
- **严重度**: 中（子循环失败被当成功，污染主循环的决策依据）
- **状态**: 已提炼

## 1. Bug 描述

`runtime/src/tools/builtin/skill-tool.ts` 调用子 AgentLoop 后不检查 terminated：

```typescript
// 原版（bug）
const loop = new AgentLoop({ ... });
const result = await loop.runL1(input);
return result.finalText;  // ← 不检查 result.terminated
```

**问题**：子 AgentLoop 可能因以下原因被终止：
1. LLM 连续失败 3 次（loop-monitor 3-strike 触发）
2. 重复模式检测（工具调用循环）
3. budget 超限

此时 `result.terminated = true`，`result.finalText` 是：
- 错误占位文本（如 `[循环异常：检测到工具调用重复模式，已终止]`）
- 或空串

但 skill-tool 直接返回 finalText，调用方（agent-loop L1）把它当成功的技能输出 → "无信号当成功"同类 bug（与 M3 进阶-4 trae stub 同类）。

## 2. 修复

```typescript
// 修复后
const result = await loop.runL1(input);
if (result.terminated) {
  throw new Error(
    `Skill "${skillName}" terminated: ${result.terminationReason ?? 'unknown reason'}`,
  );
}
return result.finalText;
```

修复后：terminated 时 throw error，上层 toolRegistry.execute → agent-loop catch 记录为 isError（不再当成功输出）。

## 3. 根因分析

### 表层原因
skill-tool 直接返回 finalText，没检查 terminated 标志。

### 机制原因
AgentLoop.runL1 的返回值 `AgentLoopResult` 有两个字段：
- `finalText: string` — 最终输出文本（即使是错误占位也有值）
- `terminated: boolean` — 是否被异常终止

skill-tool 只读了 finalText，没读 terminated。这是"返回值部分消费"问题 — 调用方只取了部分字段，忽略了状态字段。

### 根因
**跨循环的 terminated 状态必须显式传播**。当一个循环（子 AgentLoop）被另一个循环（主 agent-loop）调用时，子循环的终止状态必须显式检查并传播，不能只取 finalText 当成功。

这与 tianhuo-cicd-loop.ts 形成对比 — 后者正确检查了 `tianhuoResult.terminated`（L107-113）。模式不一致导致 skill-tool 漏检。

## 4. 待提炼的铁律（候选，待人工确认）

### E85（候选）— 跨循环 terminated 状态必须显式传播

**适用场景**：任何"循环调用循环"的场景（主循环调子循环 / L2 调 L1 / orchestrator 调 AgentLoop）。

**规则**：
- 子循环返回值含 `terminated` 状态字段时，调用方必须显式检查
- 不能只取 `finalText` / `output` 等内容字段当成功结果
- terminated 时必须 throw error 或返回 error 标识（不能静默当成功）
- 检查逻辑应集中在一处（避免每个调用点各自实现，导致遗漏）

**反例（错误做法）**：原 skill-tool 只取 finalText，不检查 terminated。

**正例（正确做法）**：
- tianhuo-cicd-loop.ts：检查 `tianhuoResult.terminated` → 返回 achieved:false
- 修复后的 skill-tool：检查 `result.terminated` → throw error

### E86（候选）— 返回值部分消费陷阱

**适用场景**：任何返回多字段对象（含状态字段 + 内容字段）的接口。

**规则**：
- 接口返回多字段时，状态字段（terminated / isError / success）和内容字段（finalText / output / content）必须一起消费
- 只取内容字段忽略状态字段 = 把"可能失败的结果"当成功
- 设计层面：状态字段应放在内容字段之前（语义优先），或用 discriminated union 强制消费

**反例**：原 skill-tool `return result.finalText` 只取内容字段。
