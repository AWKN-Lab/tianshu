## 教训

多 Agent / 跨会话协作的 git 工作流里，**任何 git 状态判断（ahead/behind/status/branch -r）之前必须先 `git fetch`**，绝不允许基于 status 缓存作决策。

- 证据 1：本 session 开头根据 `git status` 缓存说 "ahead 1 commit = b117af2" → fetch 后实际 ahead 2+1，且 b117af2 早被推进。
- 证据 2：同一 git 路径下，缓存里的 "modified 9 + untracked 79" 跟 fetch 后的 ahead 链都不可信。

## 反例

```bash
# 错误：直接读 git status 缓存就推送
git status -sb   # 输出 "ahead 1"
git push tianshu main   # 实际错过了 ahead 链里另 2 个别人 commit

# 正确：先 fetch + 看完整 log
git fetch tianshu main --no-tags
git log tianshu/main..main --oneline   # 看真实领先链
```

## 触发词

推送 / git push / git status / ahead / fetch / 推送前 / 同步前 / 多 Agent / 跨 session / git status 缓存 / 何时 fetch

## 验收

- 任意 git 操作的第一条命令**应当是** `git fetch <remote> <branch>` 或本地等价的 refresh
- 不依赖 `git status` 缓存里的 "ahead N" 字面值
- 对 ahead/behind 必须 `git log remote..local --oneline` 重新对账再行动
