# EXP-DRV-20260723-007 — agent-loop runL2 token 双计 bug（累计值 vs 增量值的语义陷阱）

- **类型**: derived（推导经验，人工沉淀）
- **日期**: 2026-07-23
- **触发**: 用户要求"实现完整的自主、自动、自进化的闭环 /goal" — 批判性深度分析 agent-loop.ts runL2 时发现 token 计数 bug
- **作者**: AI + 用户监督
- **严重度**: 中（L2 多轮循环时预算被多计，导致 budgetGate 误判超限 → 循环被错误终止）
- **状态**: 已提炼

## 1. Bug 描述

`runtime/src/core/agent-loop.ts` runL2 复用同一 AgentLoop 实例调用 runL1，`this.totalTokens` 跨 cycle 累积。原版 `recordCycle(goalId, l1Result.totalTokens, ...)` 传累计值：

```typescript
// 原版（bug）
while (l2Cycle < this.config.maxL2Cycles) {
  const l1Result = await this.runL1(userInput);
  // this.totalTokens 在 runL1 内部 += resp.usage.totalTokens（跨 cycle 累积）
  // l1Result.totalTokens 返回的是 this.totalTokens（累计值，不是本轮增量）

  goalManager.recordCycle(this.config.goalId, l1Result.totalTokens, cycleDurationMs);
  // ← bug：传的是累计值
}
```

但 `recordCycle` 内部是 `consumed.tokens += tokens`（增量累加）：

```typescript
// goal-manager.ts recordCycle（正确语义：增量累加）
goal.budget.consumed.cycles += 1;
goal.budget.consumed.tokens += tokens;  // ← 增量累加
```

**问题**：3 轮 cycle，每轮实际消耗 [100, 150, 150]，累计值 [100, 250, 400]：
- 旧版：recordCycle(100) + recordCycle(250) + recordCycle(400) → consumed.tokens = 750 ❌
- 实际：应为 100 + 150 + 150 = 400
- 多计 350 tokens（87.5% 虚高）

## 2. 修复

```typescript
// 修复后：用增量 token
let prevCumulativeTokens = 0;
while (l2Cycle < this.config.maxL2Cycles) {
  const l1Result = await this.runL1(userInput);
  // l1Result.totalTokens 仍是累计值（this.totalTokens）

  const incrementalTokens = l1Result.totalTokens - prevCumulativeTokens;
  prevCumulativeTokens = l1Result.totalTokens;
  goalManager.recordCycle(this.config.goalId, incrementalTokens, cycleDurationMs);
  // ← 修复：传增量值
}
// buildResult 仍返回 this.totalTokens（正确累计值，不受影响）
```

修复后：recordCycle(100) + recordCycle(150) + recordCycle(150) → consumed.tokens = 400 ✅

## 3. 根因分析

### 表层原因
runL2 调用方（agent-loop.ts）和被调方（goal-manager.recordCycle）对 `tokens` 参数的语义理解不一致：
- 调用方传：累计值（this.totalTokens 跨 cycle 累积）
- 被调方收：增量值（consumed.tokens += tokens）

### 机制原因
AgentLoop 类的 `this.totalTokens` 字段设计为"实例生命周期内的累计 token"，runL1 每次调用都在此基础上累加。这个语义对"单次 runL1 调用"是正确的（返回值就是本次消耗）。

但 runL2 在同一实例上多次调用 runL1，导致 `l1Result.totalTokens` 从"本次消耗"变成了"截至本次的累计消耗"。调用方没意识到这个语义变化，直接把累计值当增量传给 recordCycle。

### 根因
**累计值和增量值是两种不同的语义，不能混用**。当一个字段（this.totalTokens）在循环中累积时，它的"返回值含义"会随调用次数变化：
- 第 1 次调用：返回值 = 本次增量 = 累计值（两者相等）
- 第 N 次调用：返回值 = 累计值 ≠ 本次增量（两者不等）

接口契约必须明确："返回的是累计值还是增量值"，消费方必须按契约处理。原版两边契约不一致导致 bug。

## 4. 待提炼的铁律（候选，待人工确认）

### E83（候选）— 累计值和增量值的语义不能混用

**适用场景**：任何涉及"累积量"的接口（token 计数 / 时长统计 / 资源用量 / 进度跟踪）。

**规则**：
- 累积字段（如 `this.totalTokens`）的返回值语义会随调用次数变化：
  - 首次调用：返回值 = 本次增量 = 累计值（巧合相等）
  - 后续调用：返回值 = 累计值 ≠ 本次增量
- 消费方必须明确区分"要的是累计值还是增量值"：
  - 需要累计值：直接用返回值
  - 需要增量值：用 `返回值 - 上次返回值`
- 接口契约必须显式声明返回的是哪种语义

**反例（错误做法）**：原 agent-loop.ts 把累计值当增量传给 recordCycle（`+=` 语义）。

**正例（正确做法）**：
- tianhuo-cicd-loop.ts 每轮 `new AgentLoop(...)`，实例隔离，返回值就是本轮增量（正确）
- 修复后的 runL2：`incremental = l1Result.totalTokens - prevCumulativeTokens`

### E84（候选）— "假达停止条件"的两个方向

**适用场景**：任何基于累积量判断"是否达停止条件"的逻辑（budgetGate / 验收门禁 / 进度条）。

**规则**："假达停止条件"有两个方向，都要防：
- **假成功（假"已达"）**：该停不停 / 不该通过却通过
  - 实例：trae stub 假成功（EXP-DRV-005）/ hook fail-open（EXP-DRV-006）
  - 修复方向：fail-closed，无信号不能当成功
- **假失败（假"未达"）**：不该停却停 / 该通过却不通过
  - 实例：token 双计导致 budgetGate 误判超限（本经验）
  - 修复方向：准确计量，不能多计也不能少计

**对比表**：
| 方向 | bug 表现 | 影响 | 修复 |
|------|----------|------|------|
| 假成功 | 无信号当成功 | 停止条件被误导通过 | fail-closed |
| 假失败 | 多计导致误判超限 | 循环被错误终止 | 准确计量（增量 vs 累计） |
