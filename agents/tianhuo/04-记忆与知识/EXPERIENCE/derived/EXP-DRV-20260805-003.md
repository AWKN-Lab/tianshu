# EXP-DRV-20260805-003｜1 commit 多领域取舍条件

**状态**: DRAFT
**类型**: DERIVED
**适用范围**: 大型 working tree 汇总推送场景（用户授权"全部"时）
**关联 commit**: 81e52ef (125 files / 11957 insertions / 7 个独立领域)

## 教训

**用户说 "全部" ≠ 必然是 1 个 commit**。两类取舍：
- 若用户授权写"add+commit+push 全部"，可按字面 1 commit，但 commit message 必须详尽列举每个领域
- 若用户写"更新文件"但没说 commit 边界，**必须先问** "全入 1 commit 还是按领域拆"——不能默认

## 反例

```bash
# 反例 A：把 7 个不相关领域塞进 1 commit 不询问
git add .   # 也可能卷入 IDE 缓存
git commit -m "chore: 同步"   # message 没拆解，revert 难
git push

# 反例 B：拆得过细，反而违背"全部"字面授权
# 用户授权"全部"时不应该擅自拆 6 个 commit
```

## 触发词

全部 / 全部入库 / 一次性 / 一起推 / bulk commit / 大杂烩 / 综合 commit / chore sync / 拆 commit / atomic

## 验收

- commit message 必须包含**领域清单 + 文件计数**（如本例 125 files/7 领域）
- 当 modified + untracked ≥ 10 个且跨 ≥ 3 个领域时，**默认询问**用户 commit 拆分意图
- 不向用户推荐 "拆 vs 单" 时，须在 commit message 显式标 `chore(sync)` 或 `wip:` 标注非 atomic

## 配套 commit message 模板

```
chore(sync): [简短标题]

本 commit 一次性提交 [N 个领域]：
一、[领域 1]
- 文件 A
- 文件 B
二、[领域 2]
...

注：ahead commits [SHA 链] 由 [来源 session] 提交，本 commit 不含。
```
