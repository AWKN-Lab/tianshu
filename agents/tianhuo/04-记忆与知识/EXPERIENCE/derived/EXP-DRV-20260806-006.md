# EXP-DRV-20260806-006｜Ahead 链推送前必须按整体变更范围运行完整门禁

## 适用范围

包含多个提交或 Runtime 改动的分支推送、pre-push 门禁和本地 CI 预演。

## 教训

逐个提交运行轻量门禁无法覆盖提交组合后的链式效应。Ahead 链应被视为一次完整推送事件，根据上游分支到当前 HEAD 的整体 diff 选择门禁。包含 Runtime 改动或提交数达到阈值时，应在 push 前运行 full 档，避免把依赖缺失、契约断链和测试状态污染留到 push-time 才发现。

## 反例

```text
错误：每个 commit 单独跑轻量检查，整条 ahead 链从未跑 full 档。
正确：计算 upstream..HEAD 的整体变更 → 运行 full 档 → 取得完整退出码 → 再 push。
```

## 安全边界

- 门禁只读取变更范围，不自动提交或推送。
- 临时目录和测试数据库必须按进程与时间唯一化并清理。

## 验收

- Ahead 链包含 Runtime 改动时，push 前 full 档完整通过。
- Push-time 不出现本地可复现的新问题。
- 门禁证据记录 HEAD SHA、变更范围和各阶段退出码。

## 失效条件

当远端 CI 与本地 full 档完全等价，并能在提交进入主分支前强制执行时，本地 full 预演可降级为风险触发式。
