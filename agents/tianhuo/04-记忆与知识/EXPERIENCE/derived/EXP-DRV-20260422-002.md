## 经验内容

### 问题/场景
天火智能体在执行任务时遇到技术障碍，需要明确的升级处理时间线。

### 解决方案/发现
建立了三级卡住处理协议，层层升级：

```
10秒  → memory_search + web_search（并行）
30秒  → browse_page + sessions_spawn（并行工具调用）
60秒  → 启动5步探索循环
```

5步探索循环：
1. 文档检索（内部记忆 → 外部文档 → 社区）
2. 日志分析（操作日志 → 错误日志 → 系统日志）
3. 多路径尝试（方案A → 方案B → 方案C）
4. 方案验证（小规模测试 → 完整验证 → 确认）
5. 反思进化（写回MEMORY.md → 更新最佳实践 → 通知）

### 关键洞察
卡住处理的核心是「不放弃但也不盲目」：
- 10秒内快速尝试（成本低）
- 30秒内并行搜索（扩大范围）
- 60秒后系统化探索（深度优先）

### 可复用模式
```
遇到障碍 → 计时 → 10秒尝试 → 30秒扩展 → 60秒系统化
```

### 实施建议
1. 任何任务执行时，保持计时意识
2. 超过60秒必须进入5步循环
3. 5步循环后无论成功与否都要写回MEMORY
