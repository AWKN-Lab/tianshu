# EXP-DRV-20260806-001｜Windows 下载服务器二进制：SSH 管道是文本协议，必须服务器端落盘 + scp

**状态**: DRAFT
**类型**: DERIVED
**适用范围**: Windows 本机（PowerShell）⇄ Linux 服务器之间的任何大文件/二进制传输（tar.gz、数据库 dump、媒体资产）
**关联 commit**: 无（本次未涉及 git）

## 教训

Windows PowerShell 的管道是**文本协议**：`ssh host "cat big.tar.gz" | Set-Content -AsByteStream out.tar.gz` 会把 ssh 原生 stdout 按文本行处理，`Set-Content -AsByteStream` 报"Cannot proceed with byte encoding"，最终产物 0 字节——且因传输已完成只等写入，命令超时 10 分钟才发现失败。

- 证据 1：2026-08-06 下载 /srv/time-theater 旧 release（602M×2）用管道写法 → 0 字节文件 + 600s 超时
- 证据 2：改用"服务器端 `tar czf /tmp/x.tar.gz` → `scp` 下载"后，483M×2 + 954M 全部成功，SHA256 与服务器一致

## 反例

```powershell
# 错误：SSH 管道到本地文件（文本协议，二进制必坏）
ssh -i key root@host "cat /srv/x.tar.gz" | Set-Content -Path out.tar.gz -AsByteStream

# 正确：服务器端先落盘，再 scp（二进制安全）
ssh -i key root@host "tar czf /tmp/x.tar.gz /srv/xxx"
scp -i key root@host:/tmp/x.tar.gz D:\backup\
ssh -i key root@host "rm -f /tmp/x.tar.gz"
# 落盘后必做：本地 Get-FileHash SHA256 与服务器 sha256sum 比对
```

## 触发词

下载服务器文件 / scp / SSH 管道 / Set-Content / tar 管道 / 二进制传输 / 0 字节文件 / 下载超时 / 大文件传输 / Windows 下载

## 验收

- 任何服务器→Windows 的二进制/大文件传输，第一条命令是服务器端 `tar czf`/`pg_dump` 落盘，再用 scp/rsync 下载
- 禁止 `ssh ... | Set-Content -AsByteStream` 类管道写法
- 下载完成后 SHA256 双方比对（服务器 `sha256sum` vs 本地 `Get-FileHash`）才允许删除服务器原件
