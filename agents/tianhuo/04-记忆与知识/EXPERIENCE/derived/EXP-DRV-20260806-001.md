# EXP-DRV-20260806-001｜Windows 下载服务器二进制：服务器端落盘后使用二进制安全传输

## 适用范围

Windows PowerShell 与 Linux 服务器之间的大文件或二进制传输。

## 教训

PowerShell 管道会按对象和文本语义处理原生程序输出。把 `ssh "cat archive"` 直接管道到本地文件，可能造成编码错误、零字节文件或延迟暴露的损坏。二进制资产应先在服务器端生成文件，再使用 `scp`、SFTP 或其他二进制安全协议传输。

## 反例

```powershell
# 禁止：把二进制 stdout 直接交给 PowerShell 文本管道
ssh host "cat <REMOTE_ARCHIVE>" | Set-Content -Path <LOCAL_ARCHIVE> -AsByteStream

# 推荐：远端落盘，再使用二进制安全传输
ssh host "tar czf <REMOTE_TEMP_ARCHIVE> <PROJECT_PATH>"
scp host:<REMOTE_TEMP_ARCHIVE> <LOCAL_BACKUP_DIR>
```

## 安全边界

- 不在经验文件中保存真实服务器地址、用户、密钥路径、项目绝对路径或完整哈希。
- 临时归档仅在完整性验证成功后删除。

## 验收

- 本地文件非零且格式可读取。
- 服务器与本地完整性校验一致。
- 传输失败时不删除源文件。

## 失效条件

当统一文件传输服务提供端到端校验、重试和审计后，本经验可并入平台传输规范。
