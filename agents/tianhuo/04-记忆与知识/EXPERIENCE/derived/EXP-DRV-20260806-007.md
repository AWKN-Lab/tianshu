# EXP-DRV-20260806-007｜Windows Node 工具调用：先验证本地依赖，再构造可控 PATH

## 来源证据

Runtime 记录到 `spawn tsc ENOENT`。同类门禁执行中还出现过本地 `typescript` 包缺失和 `node_modules/.bin` 不可达，单凭报错不能直接归因于 PowerShell。

## 教训

执行项目级 Node 工具时，诊断顺序必须是：依赖是否安装 → 本地二进制是否存在 → cwd 是否正确 → 子进程 PATH 是否包含项目 `.bin` → 命令模板是否适配当前平台。只有前四项成立后，才能把问题归为平台 PATH 注入。

## 反例

```text
错误：看到 ENOENT 就直接修改系统 PATH。
正确：验证 node_modules/typescript、node_modules/.bin/tsc.cmd、cwd 和 spawn env，再选择 npm run、npm exec 或绝对本地二进制路径。
```

## 工程规则

- 优先通过 `npm run <script>` 调用项目工具。
- 直接 spawn 时使用项目本地可执行文件，并显式传递受控 cwd/env。
- 不依赖用户全局安装或机器级 PATH。
- 错误回执必须区分 `DEPENDENCY_MISSING`、`LOCAL_BIN_MISSING`、`PATH_MISSING` 和 `COMMAND_NOT_FOUND`。

## 验证

- 删除全局 TypeScript 后，项目门禁仍能通过本地依赖执行。
- 清空外部 PATH 后，受控执行仍能定位项目 `.bin`。
- 删除本地 TypeScript 后，错误明确报告依赖缺失，不伪装成 PATH 问题。

## 授权边界

只允许修改项目内命令调用和门禁脚本，不修改系统环境变量，不安装全局依赖。

## 失效条件

当所有 Node 工具统一由包管理器执行器或 hermetic build 环境管理后，本经验可并入统一执行器规范。
