# EXP-DRV-20260723-011 — recordCycle-before-budgetGate 顺序 + checkBudget 防御性 fail-closed

- **类型**: derived（推导经验，人工沉淀）
- **日期**: 2026-07-23
- **触发**: 继续批判性审查 runtime 模块，发现 prd-centric-loop 和 tianhuo-cicd-loop 的 recordCycle 在 budgetGate 之后调用 → 假成功
- **作者**: AI + 用户监督
- **严重度**: 高（影响 budget 控制有效性，可能导致预算超限仍标记 achieved）
- **状态**: 已提炼

## 1. 缺口描述

M3 进阶-9 修了 prd-centric-loop 的 recordCycle token 双计 bug，但没修"顺序错位"：

- prd-centric-loop：先 `budgetGate(...)` 后 `recordCycle(...)` → budgetGate 评估时本轮 token 还没累加到 `goal.budget.consumed`
- tianhuo-cicd-loop：先 `evaluateTianhuoCicdStop(...)`（含 budgetGate）后 `recordCycle(...)` → 同样问题

**后果**：如果本轮 token 消耗让 budget 超限，budgetGate 仍判断 passed=true（因为拿不到本轮消耗）→ 假成功 → updateGoal(achieved) → goal 标记完成但实际预算已超。

## 2. 修复

### 2.1 prd-centric-loop.ts

原版顺序：
```typescript
const budgetResult = await budgetGate({ ... });  // 1. budgetGate（拿不到本轮 token）
const achieved = ... && budgetResult.passed;
const incrementalTokens = totalTokens - prevCumulativeTokens;
gm.recordCycle(config.goalId, incrementalTokens, 0);  // 2. recordCycle（本轮 token 才累加）
```

修复后顺序：
```typescript
const incrementalTokens = totalTokens - prevCumulativeTokens;
gm.recordCycle(config.goalId, incrementalTokens, 0);  // 1. recordCycle 先（本轮 token 累加）
const budgetResult = await budgetGate({ ... });  // 2. budgetGate 能拿到真实累计
const achieved = ... && budgetResult.passed;
```

### 2.2 tianhuo-cicd-loop.ts

原版顺序：
```typescript
const stopEval = await evaluateTianhuoCicdStop({ ... });  // 含 budgetGate
if (stopEval.achieved) { gm.updateGoal(achieved); return; }
feedbackFromLastCycle = reviewResult.finalText;
gm.recordCycle(config.goalId, tianhuoResult.totalTokens + reviewResult.totalTokens, 0);  // durationMs=0 bug
```

修复后顺序：
```typescript
const cycleDurationMs = Date.now() - cycleStartedAt;  // 修复 durationMs=0 bug
gm.recordCycle(config.goalId, tianhuoResult.totalTokens + reviewResult.totalTokens, cycleDurationMs);
const stopEval = await evaluateTianhuoCicdStop({ ... });  // budgetGate 能拿到真实累计
if (stopEval.achieved) { gm.updateGoal(achieved); return; }
feedbackFromLastCycle = reviewResult.finalText;
// recordCycle 已在上面调用，不再重复
```

附带修复 durationMs=0 bug：原版传 0，现改为 `Date.now() - cycleStartedAt`。

## 3. 实施中发现的额外 bug：checkBudget 防御性缺失

测试 M3 进阶-15 时，我传错了 budget 格式（`max: { tokens: 100 }` 而非 `maxTokens: 100`），budgetGate 返回 details 是 "预算使用 NaN%"。

**根因**：`checkBudget` 直接 `c.tokens / b.maxTokens`，若 `b.maxTokens` 是 undefined：
- `c.tokens / undefined` = `NaN`
- `Math.max(NaN, ...)` = `NaN`
- `NaN >= 1.0` = `false` → `exceeded = false` → budgetGate passed=true → **假成功**

这是 fail-open 行为，对安全接口（预算约束）是错误的。

**修复**：添加 `Number.isFinite` 防御性检查，字段缺失或非正数时 fail-closed（exceeded=true, maxUsage=Infinity）。

## 4. 待提炼的铁律（候选，待人工确认）

### E93（候选）— 消耗记录必须在预算评估之前调用

**适用场景**：任何"先消耗资源、后评估预算"的循环（agent loop / pipeline / workflow）。

**规则**：
- `recordCycle`（消耗累加）必须在 `budgetGate`（预算评估）之前调用
- 否则 budgetGate 拿不到本轮真实消耗 → 误判未超限 → 假成功
- 顺序：先累加消耗 → 再评估预算 → 再判断停止条件

**反例**：
```typescript
const budgetResult = await budgetGate({ goalId });  // 拿不到本轮 token
gm.recordCycle(goalId, tokens, durationMs);  // 本轮 token 才累加
```

**正例**：
```typescript
gm.recordCycle(goalId, tokens, durationMs);  // 先累加
const budgetResult = await budgetGate({ goalId });  // 能拿到真实累计
```

### E94（候选）— 安全接口必须 fail-closed

**适用场景**：任何"拒绝/通过"决策接口（预算检查 / 权限校验 / 配额检查 / 安全扫描）。

**规则**：
- 输入字段缺失/无效时返回"拒绝"而非"通过"
- 宁可误停（false positive：误判超限停循环）不可误放（false negative：误判未超限放行）
- fail-closed 的反义是 fail-open — 后者适用于"信息接口"（如日志查询），不适用于安全接口

**反例**：
```typescript
const u2 = c.tokens / b.maxTokens;  // maxTokens=undefined → NaN
const exceeded = NaN >= 1.0;  // false → 假成功
```

**正例**：
```typescript
if (!Number.isFinite(b.maxTokens) || b.maxTokens <= 0) {
  return { exceeded: true, maxUsage: Infinity, ... };  // fail-closed
}
const u2 = c.tokens / b.maxTokens;
```

**判定标准**：接口的"假成功"代价 vs "假失败"代价
- 假成功代价高（放行危险操作）→ fail-closed
- 假失败代价高（误停正常流程）→ fail-open
- budgetGate 假成功 = 预算超限仍标记 achieved → 高代价 → fail-closed
