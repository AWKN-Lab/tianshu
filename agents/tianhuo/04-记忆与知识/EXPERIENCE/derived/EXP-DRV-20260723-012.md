- `corrections-ledger.ts` — 错误台账（record / list / countByFingerprint / resolveByFingerprint）

**但**：全局搜索 `getCorrectionsLedger().record(` 发现**零调用**。

corrections-ledger.ts 注释写着设计意图：
```
*   gate FAIL → recordCorrection({ source: 'reviewGate', ... })
*   loop-monitor 3-strike → recordCorrection({ source: 'loop_monitor', ... })
```

但这些只是设计注释，**从未实现**。结果：
- corrections-ledger 永远为空
- pattern-detector 永远返回 `[]`
- experience-writer 永远写 0 个文件
- **自进化闭环是死代码**，看起来在工作但实际什么也没做

**1. quality-gates.ts** — 添加 `recordGateFailures()` 函数：
```typescript
export function recordGateFailures(goalId, results): void {
  const ledger = getCorrectionsLedger();
  for (const r of results) {
    if (r.passed) continue;  // 只记录 FAIL
    ledger.record({ goalId, source: r.name, severity: ..., errorText: r.details });
  }
}
```

## 4. 候选铁律 E95

**E95：自进化闭环（或任何 data-driven pipeline）必须有端到端连通性验证**

- **适用情境**：pipeline 由多个组件串联组成（A → B → C → D），每个组件单独工作正常
- **铁律**：不只验证各组件单独工作，还必须验证"入口 → 处理 → 出口"整条链路有真实数据流过。具体做法：
  1. 在入口注入测试数据（模拟真实输入）
  2. 验证中间组件收到了数据（不是空输入）
  3. 验证出口产出了真实结果（不是空输出）
  4. 验证状态变更确实发生（如 corrections 被 resolved）
- **反例**：四件套全部实现 + hook 已注册 + 各组件单元测试通过 → 看起来完整，但 record() 从未被调用 → 整条链路跑空数据 → 死代码
- **正例**：verify-evolve-loop.ts 在入口 record 3 次相同错误 → 验证 pattern-detector 检测到 pattern → 验证 experience-writer 写了文件 → 验证 corrections 被 resolved → 验证 resolve 后 detect 返回 []（完整闭环验证）

**与 E73 的关系**：E73 说"失败必须留证据"，E95 补充"证据收集链路本身也必须验证连通" — 否则证据收集机制本身就是"假达停止条件"。
