## 2. 根因分析

### Bug 1 (M3 进阶-22)：autoPauseIfBudgetLimited 绕过状态机 — high

**代码**：
```typescript
const status = checkBudget(goal);
if (status.exceeded && goal.state !== 'budget_limited') {
  goal.state = 'budget_limited'; // 直接设，不查 canTransition
  // ...
}
```

**问题**：直接 `goal.state = 'budget_limited'`，不检查 `canTransition(goal.state, 'budget_limited')`。
- `GOAL_TRANSITIONS['paused'] = ['active', 'unmet']`，不含 `budget_limited`
- 用户 `pauseGoal` 后，系统级 `autoPauseIfBudgetLimited` 仍把 paused 的 goal 转 budget_limited
- 违反用户暂停意图（系统预算覆盖用户独占操作）
- 与 M3 进阶-10 `updateGoal` 绕过状态机同类（直接设 state 不查 canTransition）
- 违反硬约束 "State transitions must use the state machine"

**影响链**：paused goal → autoPause 强转 budget_limited → 用户 resumeGoal 失败（budget_limited→active 合法，但语义错位）→ 用户意图被系统覆盖

### Bug 2 (M3 进阶-23)：recordCycle 不检查 goal.state — medium

**代码**：
```typescript
recordCycle(id: string, tokens: number, durationMs: number): Goal | null {
  const goal = this.goals.get(id);
  if (!goal) return null;
  // 不检查 goal.state，直接累加消耗
  goal.budget.consumed.cycles += 1;
  // ...
}
```

**问题**：不检查 `goal.state`，即使 `paused/achieved/unmet/budget_limited` 仍记录消耗。
- **paused**：用户暂停后循环不应运行，若调用方 bug 导致仍调 recordCycle，会累加消耗
- **achieved/unmet**：终态 goal 不应再消耗 token
- **budget_limited**：已超限的 goal 不应继续累加（应在 active 转 budget_limited 时停止）
- 与 M3 进阶-22 互为因果：recordCycle 不检查状态 → autoPause 在非法状态下被触发 → 状态机绕过

**影响链**：调用方 bug → 非 active goal 仍 recordCycle → 消耗累加 → autoPause 在 paused 状态下被触发 → 状态机绕过（M3 进阶-22 的根因之一）

```typescript
recordCycle(id: string, tokens: number, durationMs: number): Goal | null {
  this.ensureLoaded();
  const goal = this.goals.get(id);
  if (!goal) return null;

  // 只有 active 的 goal 才记录消耗，其他状态 warn + 跳过
  if (goal.state !== 'active') {
    logger.warn(
      `recordCycle called on non-active goal (state=${goal.state}, id=${id}), skipping — caller should not invoke recordCycle for non-active goals`,
    );
    return goal;
  }
  // ... 后续累加逻辑不变
}
```

## 5. 候选铁律

### E98：状态机转换必须统一走 canTransition 检查（包括系统级自动转换）

**适用情境**：任何修改 `goal.state` 的代码路径，包括用户操作（pauseGoal/resumeGoal）、模型操作（updateGoal）、系统级自动操作（autoPauseIfBudgetLimited）。

**铁律**：所有状态转换必须经过 `canTransition(from, to)` 检查。禁止直接 `goal.state = newState`。系统级自动转换（如预算耗尽）不能覆盖用户独占操作（如 paused）— 当两者冲突时，用户意图优先。

**反例**：
```typescript
// 系统级自动转换，不查状态机
if (status.exceeded) {
  goal.state = 'budget_limited'; // paused 的 goal 也被强转
}
```

**正例**：
```typescript
if (status.exceeded) {
  if (!canTransition(goal.state, 'budget_limited')) {
    logger.warn(`Cannot auto-pause: ${goal.state} → budget_limited not allowed`);
    return { changed: false, goal }; // 保持原状态
  }
  goal.state = 'budget_limited';
}
```

**与 E10（updateGoal 必须检查 canTransition）的关系**：E10 是模型操作路径的约束；E98 是所有路径（含系统级自动转换）的统一约束。E98 是 E10 的泛化。

**关联防御**：recordCycle 必须检查 goal.state === 'active'，从源头阻止非 active goal 触发 autoPause（M3 进阶-23）。这是状态机完整性的"前置防御"。
