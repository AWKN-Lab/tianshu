## 经验正文

### 问题/场景
AI Agent 在面对"是否替用户执行 git config / npm config / ssh config 等系统级配置"时，倾向于默认拒绝以避免越权。但过度保守会让本可放行的合理请求被拦，反而损害协作效率。

实际风险不在"执行本身"而在"执行的方式是否安全"。需要从"一刀切拒绝"切换到"四要素自检"。

### 核心结论/原则
**四要素自检清单**（任一不满足 = 拒绝并说明缺失哪条；全满足 = 放行并简报执行结果）：

1. **明确授权（静默 vs 显式）**
   - ✅ 用户在消息中明示"用 @部署 执行" / "可以执行第三阶段" / "允许 git config"等
   - ❌ 用户只是描述目标未提及工具链（如"启用钩子"未提 `git config core.hooksPath`）→ 先确认再执行

2. **作用域（仓库级 vs 用户级 vs 系统级）**
   - ✅ `--local` / 仓库内 `git config` 不带 scope → 写入 `.git/config`
   - ⚠️ `--global` 改 `~/.gitconfig` → 影响所有仓库，需更明确授权
   - ❌ `--system` 改 `/etc/gitconfig` / Windows 的 `%PROGRAMFILES%\Git\etc\gitconfig` → 拒绝，除非用户显式说"全局配置"

3. **可逆性（一键回滚 vs 不可逆）**
   - ✅ `git config core.hooksPath .githooks` → `git config --unset core.hooksPath` 一键回退
   - ⚠️ `git config --global core.editor nano` → 用户级，可逆但影响范围大
   - ❌ `git filter-branch` / `git push --force` / 删 reflog → 不可逆或破坏审计链，拒绝

4. **指向资产（已审查 vs 未审查）**
   - ✅ 指向已提交、已过代码评审的资产（如 `.githooks/pre-push`、`.github/workflows/*.yml`）
   - ❌ 指向本地未提交脚本、远程下载脚本、AI 临时生成未审代码 → 拒绝

**触发场景**：除 git config 外，还适用于 `npm config set`、`ssh-add`、`git remote add`、`git submodule add`、`aws configure`、`gh auth login` 等所有"修改环境配置"类工具调用。

### 适用范围
- 所有 Agent 面对"是否修改系统/用户/仓库配置"决策
- 推广到"是否执行不可逆操作"（force push、reset --hard、删分支、删远程 ref 等）

### 反例
- 用户说"启用钩子" → Agent 拒绝要求用户手动跑 → 过度保守（用户已隐含授权）
- 用户说"git config" + 全局 → Agent 直接执行 → 跳过授权边界检查（应再次确认是否真要 global）
- 用户说"删除 dev 分支" → Agent 拒绝说"我不执行破坏性操作" → 不区分"删未合并 dev"和"删已合并 dev"，过度保守
- 用户说"git config core.hooksPath .githooks" → Agent 拒绝 → 错过本应放行的合法请求

### 验证方式
- 每次拒绝时输出"四要素中第 X 条不满足"明示
- 每次放行时输出"四要素全满足：local / 可逆 / 已审查资产 / 显式授权"
- 对不可逆操作（force push、reset --hard、删除分支）默认拒绝并提示确认
- 月度回顾：是否有过度拒绝案例（用户纠正"为什么不能"）→ 校准护栏

### 失效条件
- 用户进入"完全放手"模式（明确说"以后同类操作你都自动执行"）→ 升级为三要素（去掉"明确授权"，但保留作用域/可逆/审查）
- 项目环境为一次性容器/沙箱 → 可放宽"作用域"要求
- 操作是用户高频重复且已模式化（如 `git push` → 不需要每次确认）

### 授权边界
- 仅约束 Agent 自身的"是否执行"决策，不直接修改用户的环境（除用户明确授权的当下操作）
- 不替代用户对工具/配置本身的理解和选择

### 建议目标
- 建议在 awkn-工程文档 / awkn-执行检查技能中增加"四要素自检清单"作为可复用的决策模板
- 建议在 MEMORY 中固化本规则（与既有"Git限定路径提交需先add再commit"并列）
- 建议对历史上所有"用户纠正为什么不能"事件做反向归因，复盘护栏过度保守点
