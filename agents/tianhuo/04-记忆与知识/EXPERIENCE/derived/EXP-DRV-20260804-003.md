## 经验正文

### 问题/场景
远端经 Git Data API 重建 commit 对象后，本地与远端历史内容等效但 sha 不同，形成分叉。常规 push 被拒，force push 会覆盖远端历史且破坏审计链。

### 核心结论/原则
1. **先判定分叉性质**：`git log --format=%s` 双向对比，若远端独有提交与本地最旧 N 条消息逐一相等，则为"等效历史"分叉，可安全重放。
2. **commit-tree 重放**：对本地独有提交按旧→新顺序，取各自原 tree 逐一 `git commit-tree <tree> -p <上一重放sha> -F <原消息文件>`，parent 链接到远端 tip，得到与远端线性衔接的新链。
3. **tree 一致性校验**：重放完成后 `git diff --quiet 旧HEAD 新tip` 必须为空，再 `update-ref` 移动分支（旧链留在 reflog 可回滚）。
4. **消息文件用无 BOM UTF-8**：`git log -1 --format=%B` 导出后以 UTF8Encoding($false) 写盘，避免 BOM 混入 commit message。

### 适用范围
仅适用于"消息与 tree 均可逐一匹配"的等效分叉。若远端含本地没有的真实内容（m<0）或消息不匹配，必须中止走正常 merge/rebase。

### 反例
- 远端有他人新提交时强行重放 → 覆盖他人工作
- 跳过 tree 一致性校验直接 update-ref → 内容静默漂移

### 验证方式
`git rev-parse HEAD` == `git ls-remote <remote> refs/heads/<branch>` 且 push 为快进（`old..new` 而非 `+old...new` 强推标记）。

### 失效条件
提交消息在重建时被改写（不再逐一相等）；或仓库启用分支保护禁止任何直推。

### 授权边界
只操作本地 ref 与一次普通快进 push；不执行 force push、不删除远端 ref。

### 建议目标
- 工具已固化: scripts/push-realign.ps1（fetch→等效校验→重放→tree校验→update-ref→快进推送，支持 -DryRun/-NoPush）
