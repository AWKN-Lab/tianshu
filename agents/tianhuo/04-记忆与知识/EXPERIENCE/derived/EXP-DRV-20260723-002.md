## 2. 实现内容

### 2.1 数据层：corrections-ledger.ts

新增 `corrections_ledger` SQLite 表（10 列 + 4 索引，无 FK 允许 manual 条目），封装为 `CorrectionsLedger` 类提供：
- `record(input)`: 写入一条错误（自动计算 fingerprint）
- `list(filter)`: 按 source/status/fingerprint/goalId/sinceHours 过滤
- `resolve(id, resolution, experienceId)`: 标记已解决
- `resolveByFingerprint(fp, ...)`: 批量关闭同指纹
- `countByFingerprint()`: 聚合统计
- `statsBySource()`: 按 source 分组

纯函数：
- `normalizeErrorText(text)`: 去 ANSI / 时间戳 / UUID / 绝对路径 basename / 折叠空白 + 转小写
- `computeFingerprint(source, errorText)`: sha256(source + '|' + normalized)[:16]

### 2.2 检测层：pattern-detector.ts

`PatternDetector` 三种检测模式：
1. **repeated_fingerprint**：最近 24h 内同指纹 ≥3 次（阈值与 LoopMonitor.maxConsecutiveFailures 对齐）
2. **source_burst**：1h 内同 source ≥5 次（不论指纹）
3. **goal_repeat**：同 goal 内同指纹 ≥2 次（更严格，因为同目标内重复更严重）

阈值可通过 `PatternDetectorConfig` 覆盖。

### 2.3 落地层：experience-writer.ts

- `resolveExperienceId(suggested)`: 扫描 derived 目录找 maxSeq，返回 `EXP-DRV-YYYYMMDD-(maxSeq+1)`，避免文件名冲突
- `patternToMarkdown(pattern, id)`: 生成 Markdown 草稿（含背景/模式/样本/待补充根因/待提炼铁律）
- `writeExperience(pattern)`: 写文件 + 调 `resolveByFingerprint` 自动关闭对应 corrections
- `stopExperienceExtractHook()`: session_stop hook 函数，自动扫 pattern → 写文件

### 2.4 集成层：cli.ts

- main() 默认注册 `stop:experience-extract` hook（可 `AWKN_DISABLE_EVOLVE=1` 关闭）
- main() finally 块触发 `session_stop` hook
- 新增 `evolve detect|list|resolve|stats` 4 个子命令

## 4. 发现的 3 处路径 bug（M3-4 副产物）

### 4.1 bug 模式：`process.cwd() + 'runtime/data/'` 双重 runtime

三处文件（db.ts / cron/engine.ts / experience-writer.ts）都用 `resolve(process.cwd(), 'runtime', 'data', ...)` 推算路径。这假设 cwd 是项目根。但 cli.ts 是从 `runtime/` 跑的，cwd = `D:\awkn-lab\awkn引擎\runtime`，于是路径变成 `runtime/runtime/data/...`（双重 runtime）。

**症状**：
- 测试副作用：测试在 `runtime/runtime/data/...` 下创建了 30+ 个临时经验文件（每次跑测试都污染）
- 生产隐患：CLI 跑时 db 文件创建在错误位置，跨命令调用无法共享状态

**根因**：依赖 `process.cwd()` 而非模块自身位置。`process.cwd()` 是 caller 决定的，模块不能假设它是什么。

**修复**：全部改用 `import.meta.url` + `dirname(__filename)` 推算，并支持环境变量覆盖：
- `AWKN_DB_PATH` 覆盖 db 路径
- `AWKN_DERIVED_DIR` 覆盖经验目录
- 测试用这两个变量隔离

### 4.2 bug 模式：CLI main() 异步竞态

verify-evolve-cli.ts 最初通过 `await import('../src/cli.ts')` 调用 CLI，但 cli.ts 末尾是 `main();`（无 await），import 在 main 完成前就 resolve，导致验证脚本读到空目录。

**修复**：验证脚本不通过 import cli.ts，而是直接调用 evolve 模块的 API（getPatternDetector().detect() + writeAllExperiences()）。

## 5. 经验提炼

### E76 — 模块路径推算禁用 process.cwd()，必须用 import.meta.url

**适用情境**: 任何模块需要推算自己的资源路径（db 文件、日志目录、配置文件等）时。

**铁律**: 模块路径推算**禁用** `process.cwd()`，必须用 `import.meta.url` + `dirname(fileURLToPath(import.meta.url))`。`process.cwd()` 是 caller 的当前目录，模块不能假设它是什么。CommonJS 的 `__dirname` 在 ESM 下要用 `import.meta.url` 等价替换。

**反例**:
```ts
const DB_PATH = resolve(process.cwd(), 'runtime', 'data', 'awkn-engine.db');
// 从 runtime/ 跑 cli.ts → 路径变 runtime/runtime/data/awkn-engine.db（双重 runtime）
```

**正例**:
```ts
const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);
// 模块自身位置 src/store/db.ts → 上溯 2 级到 runtime/，再加 data/
const DB_PATH = process.env.AWKN_DB_PATH
  ?? resolve(__dirname, '..', '..', 'data', 'awkn-engine.db');
// 同时支持环境变量覆盖（测试用）
```

### E77 — 测试隔离必须覆盖"被测模块写的文件"，不能只清"测试自己创建的目录"

**适用情境**: 测试调用会写文件的模块时。

**铁律**: 测试隔离必须覆盖**被测模块写的所有文件**，不能只清"测试自己创建的临时目录"。如果模块用 `process.cwd()` 推算路径，测试 cwd 不一致就会污染其他位置（如本案例中 30+ 个文件被写到 `runtime/runtime/data/...`）。

**反例**:
```ts
beforeEach(() => {
  // 测试只清自己的临时目录，但被测模块可能写到其他位置
  if (existsSync(TEST_DERIVED_DIR)) rmSync(TEST_DERIVED_DIR, { recursive: true });
});
// 结果：30+ 个 EXP-DRV-20260722-NNN.md 文件被写到 runtime/runtime/data/...
```

**正例**:
```ts
beforeEach(() => {
  // 用环境变量强制被测模块写到测试隔离目录
  process.env.AWKN_DERIVED_DIR = TEST_DERIVED_DIR;
  // ...
});
// 模块读取环境变量覆盖默认路径
const DIR = process.env.AWKN_DERIVED_DIR ?? defaultPath;
```

### E78 — 异步 CLI 入口必须在文件末尾用 await main() 或不暴露 main 给外部

**适用情境**: CLI 入口文件用 top-level `main();` 调用时。

**铁律**: CLI 入口的 main() 调用必须 `await main();`（top-level await in ESM）或保留为 fire-and-forget 但**禁止外部通过 import 调用**。如果测试需要驱动 CLI，应该直接 import 内部 handler 函数（如 `handleEvolve`），不要 import 整个 cli.ts（因为 `main()` 会自动执行，且与测试逻辑竞态）。

**反例**:
```ts
// cli.ts
async function main() { /* ... */ }
main();  // 无 await

// verify-cli.ts
await import('../src/cli.ts');  // import 完成 ≠ main() 完成
console.log(readFiles());  // 经常读到空目录
```

**正例**:
```ts
// 方案 A：top-level await（ESM 支持）
await main();

// 方案 B：测试直接调内部 handler
const evolve = await import('../src/evolve/experience-writer.js');
const patterns = getPatternDetector().detect();
evolve.writeAllExperiences(patterns);
```
