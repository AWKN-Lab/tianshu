# EXP-DRV-20260805-006｜YAML scalar 含"冒号+空格"必须加引号

**状态**: DRAFT
**类型**: DERIVED
**适用范围**: GitHub Actions step name / job name / 其他"自然语言字段"在 YAML 1.2 文件中的写法
**关联事件**: 2026-08-05 编写 `.github/workflows/runtime-ci.yml` light-check job 时，step name 写成 `Light gate: TypeScript typecheck (contract 档核心)`，js-yaml 解析失败（bad indentation at `gate: TypeScript`）

## 教训

**YAML plain scalar（无引号字符串）中冒号后跟空格会被解析器视为新映射条目的开始**。这不是 bug 是 YAML 1.2 spec 行为，但 GitHub Actions 官方文档示例的 step name 全部是"无冒号自然语言"标题，掩盖了"含特殊字符要加引号"的基础规则。

容易踩坑的"自然语言字段"：
- GitHub Actions `name:` 字段（step / job / workflow 都有）
- `description:` 字段
- commit message、PR 标题等通过 GitHub UI 输入的场景
- 任何把"人类语言标题"塞进 YAML 字段的地方

触发"必须加引号"的敏感字符清单（YAML 1.2 plain scalar 限制）：
- `:` 后跟空格或行尾（映射条目标记）
- `#` 行首或前导空白后（注释标记）
- `&` `*`（anchor/alias 标记）
- `!` `|` `>`（tag/字面量标记）
- `[` `]` `{` `}`（流序列/映射标记）
- `,` 在流序列中
- `-` `?` `:` 在特定位置
- 含中文/非 ASCII 时某些实现需要引号（保险起见）

## 反例

```yaml
# 错误：step name 含 "冒号+空格"，YAML plain scalar 解析为新映射
- name: Light gate: TypeScript typecheck (contract 档核心)
  run: npm run typecheck
# 报错：bad indentation of a mapping entry at line N
# 根因：`gate:` 后跟空格，YAML 把它当 mapping key，
#       期望 value 是另一个字段，但 value = "TypeScript ..."
#       缩进不匹配，解析失败

# 正确 1：加单引号（推荐，最稳）
- name: 'Light gate: TypeScript typecheck (contract 档核心)'
  run: npm run typecheck

# 正确 2：加双引号（需要转义内部双引号）
- name: "Light gate: TypeScript typecheck (contract 档核心)"
  run: npm run typecheck

# 正确 3：避免冒号（重写标题）
- name: Light gate - TypeScript typecheck (contract 档核心)
  run: npm run typecheck
```

3. **保存后实测解析**（不靠"YAML 应该对"的推断）：
