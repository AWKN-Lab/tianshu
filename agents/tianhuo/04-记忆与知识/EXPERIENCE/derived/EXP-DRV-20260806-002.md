## 教训

2026-08-06 清理阿里云服务器：`/srv/time-theater` 堆积 954M `game-static-*.tar.gz` 备份包 + 1.8G 旧 releases。追根溯源，这些不是执行疏漏——是 awkn-部署 技能 E-A10"备份（必须）"章节**明文要求**每次部署前 `cp -r assets assets.bak-$(date)`，旧项目修复四步法还要求 `tar czf backup-before-fix`。规则自 2026-05 起指导每次部署都制造服务器端备份，而 GIT 早已成为所有项目的备份源，规则没跟着演进。

- 证据 1：E-A10 原文（v2.8.1 前）"部署前备份：cp -r <dist-dir> <dist-dir>.bak-$(date…)"，案例 `assets.bak-20260530115131`
- 证据 2：用户一句话点破："我们是 GIT 做备份，服务器不能备份"——规则过期的信号由用户给出，而非流程自查
- 证据 3：改规则后（v2.9.0：GIT 即备份 + prev 分支机制），未来部署不会再产生该类产物

## 反例
