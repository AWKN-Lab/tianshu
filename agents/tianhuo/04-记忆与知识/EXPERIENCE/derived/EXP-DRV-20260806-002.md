# EXP-DRV-20260806-002｜服务器产物持续堆积：先追溯制造规则，再清理存量

## 适用范围

服务器磁盘持续出现旧版本、归档包、`.bak`、重复日志或临时产物的治理场景。

## 教训

持续堆积通常有稳定制造源。只清理存量会在下一次发布后复发。应先定位生成这些产物的部署规则、脚本或技能说明，判断规则是否已经与当前 Git、制品仓库和回滚机制冲突，再修改规则并清理历史存量。

## 反例

```text
错误：磁盘告警 → 删除一批旧文件 → 不追来源。
正确：定位制造规则 → 修正规则和保留策略 → 导出清单 → 清理存量 → 验证下一次发布不再生成。
```

## 安全边界

- 不在经验中记录真实服务器路径、主机地址和可识别包名。
- 删除前必须有清单、恢复来源和明确授权。

## 验收

- 能回答每类产物由哪条规则生成。
- 规则修改有版本记录和回滚方案。
- 下一次同类流程不再生成已禁止的冗余产物。

## 失效条件

当制品生命周期由集中平台统一管理并自动执行保留策略后，本经验可并入制品治理规范。
