## 经验正文

### 问题/场景
在 Windows（GBK console、慢网、Python 3.14）环境吸收外部 Python 项目（vendored + pip install -e + patch）时，连续发生三类事故：

1. **patch 被覆盖丢失**：`apply-patches.py --source` 的 vendor_from() 会 `shutil.rmtree(VENDORED)` 再 copytree，测试时把已打好的 core.py patch 全部清掉，且备份命令因 PowerShell 中文路径被 GBK 截获而失败 → 无备份状态下执行了不可逆操作。
2. **patch 文件乱码**：`git diff --no-index` 输出经 PowerShell pipe 落盘，stdout 被 GBK 截获，`\u2713` / `\u2192` 变成 `鉁?` 等乱码 → patch 无法 apply。
3. **ghost install**：`pip install -e <dir>` 后删除 `<dir>`，Python 仍能 `import` / crv 仍指向已删除目录 → 烟测加载到错误代码版本。

### 核心结论/原则
**R1 备份先行**：任何不可逆操作（rmtree / 覆盖 / 搬移）前，先 `Copy-Item -Recurse -Force` 到 `$tempdir` 并验证备份存在，再动手。
**R2 落盘走 UTF-8**：任何「命令输出 → 文件」路径（patch/diff/json/log）用 Python `difflib` / `open(..., encoding="utf-8")` 直接写，不走 PowerShell pipe（GBK 截获风险）。
**R3 ghost install 清理**：`pip install -e` 后不删源目录；换位置必须先 `pip uninstall` 再装新的。

### 可复用模式
```
备份先行(验证成功) → 执行不可逆操作 → 用 Python 显式 UTF-8 落盘 → pip uninstall(换位时) → 双入口烟测(CLI + python -m)
```

### 实施要点
1. 吸收任何外部 Python 项目时，patches/ + apply-patches.py + smoke-test.py 三件套
2. 改 vendored 前备份到 temp 并 `Test-Path` 验证
3. patch 生成用 difflib 而非 git diff pipe
4. 任何 editable 装完，烟测时先确认 `where crv` / `pip show` 指向正确路径

### 证据
- core.py patch 被 vendor_from() 覆盖（2026-08-04 会话）
- patch 001 含 `鉁?` 乱码导致 apply 失败（git diff pipe 事故）
- crv.exe 指向已删的 reapply-test 目录（ghost install 事故）
- 修复后：difflib 重新生成 patch、双入口烟测通过、smoke-test.py 退 0
