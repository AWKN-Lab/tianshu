## 4. 根因分析

### 表层原因（直接触发）
experience-writer 在 session_stop hook 自动写草稿，但没有对应的"消费者"来补全根因。草稿写完后无人处理。

### 机制原因（流程/系统层）
runtime 代码（TypeScript）和 skill（Markdown）是两种不同形态的模块：
- runtime 代码通过 Stop hook 自动触发，写文件到 derived 目录
- skill 需要被宿主 LLM 触发才能执行（通过 callSkill 或用户手动）
- 两者之间没有"通知"机制——runtime 写完草稿后，skill 不知道有新草稿

### 根因（不解决会复发）
**跨模块衔接缺失**。任何"生产者-消费者"模式的两模块，如果生产者写了产物但消费者不知道有产物需处理，闭环就会卡住。这不是 experience-writer 的问题，也不是 awkn-复盘总结 的问题，而是**两个模块之间的衔接协议缺失**。

## 5. 待提炼的铁律（候选 E79，待人工确认）

### E79 — 跨模块衔接必须双向标记（候选）

**适用情境**: 两个模块以"生产者-消费者"模式协作时（A 写产物，B 处理产物）。

**铁律**: 跨模块衔接必须**双向标记**：
- 生产者写产物时，必须在产物里留**消费者可识别的标记**（如"状态: 待处理"）
- 消费者的 SKILL.md/配置里必须**声明它能识别哪些标记**，并在被触发时**主动扫描**

**反例**:
```typescript
// experience-writer 写草稿，但草稿没有标准化标记
writeFileSync(filePath, content);  // content 里没有"待人工补充"标记
// awkn-复盘总结 SKILL.md 里没有"扫描 derived 目录"指令
// 结果：草稿堆积，闭环卡住
```

**正例**:
```typescript
// experience-writer 写草稿，含标准化标记
const content = `...
- **状态**: 待人工补充
## 4. 根因分析（待人工补充）
...`;
writeFileSync(filePath, content);

// awkn-复盘总结 SKILL.md 15.1 声明扫描指令
// "扫描目录：agents/tianhuo/04-记忆与知识/EXPERIENCE/derived/"
// "识别标记：状态行含 **状态**: 待人工补充"
```

**关联经验**：
- E74（防 LLM 自评自满）：消费者（LLM）只补全根因，不自动标"已提炼"
- E76（模块路径推算禁用 process.cwd()）：生产者写产物时路径必须用 import.meta.url 推算
- E57（并行 subagent 精准目标隔离）：多个生产者写不同产物时，目标不重叠天然零冲突
