# EXP-DRV-20260723-005 — trae provider stub 假成功 bug（LLM 调用失败必须 throw）

- **类型**: derived（推导经验，人工沉淀）
- **日期**: 2026-07-23
- **触发**: 用户要求"实现完整的自主、自动、自进化的闭环 /goal" — 搜索 TODO/FIXME 时发现 trae.ts 的 stub 兜底逻辑
- **作者**: AI + 用户监督
- **严重度**: 高（违反"循环里必须有说不的"铁律，导致 LLM 调用假成功 + router fallback 链从未触发）
- **状态**: 已提炼

## 1. Bug 描述

`runtime/src/llm/providers/trae.ts` 桥接失败时返回 stub 占位文本：

```typescript
// 原版（bug）
return {
  content: '[trae provider: bridge unavailable — no hook response and file bridge timeout]',
  usage: { promptTokens: 0, completionTokens: 0, totalTokens: 0 },
  provider: 'trae',
  model: req.model ?? TRAE_DEFAULT_MODEL,
  finishReason: 'stop',  // ← 假成功！看起来像正常完成
};
```

**问题**：
1. `finishReason: 'stop'` — 调用方无法区分"真响应"和"stub 兜底"
2. router 以为 trae 成功，**不触发 fallback 链**（trae→codex→minimax）
3. 停止条件评估器被误导 — verificationGate 检查"有 fresh evidence"，但 evidence 是 stub content
4. 违反 Loop Engineering 铁律 2"循环里必须有说不的"

## 2. 修复

```typescript
// 修复后
throw new Error('trae provider: bridge unavailable — no hook response and file bridge timeout');
```

修复后：
- trae 桥接失败时 throw error
- router catch error → 触发 fallback 链（trae→codex→minimax）
- 如所有 provider 失败 → router throw error → 调用方可检测

## 3. 根因分析

### 表层原因
stub 兜底的设计初衷是"保证不崩溃"——桥接失败时返回占位文本，让调用方继续运行。

### 机制原因
"保证不崩溃"和"假成功"是两个不同的概念。stub 返回 `finishReason: 'stop'` 让调用方以为 LLM 真响应了，这是"假成功"。正确的做法是 throw error，让调用方知道 LLM 不可用，决定是否重试或报错。

### 根因
**"兜底"设计违背了"失败可见"原则**。任何"失败兜底"如果让失败看起来像成功，就会误导下游。兜底应该：
- 要么 throw error（让失败可见）
- 要么返回明确的错误标记（如 finishReason: 'error'，让调用方能检测）

不应该返回 `finishReason: 'stop'` 的 stub——这让失败隐形。

## 4. 铁律（E80，待人工确认）

### E80 — LLM 调用失败必须 throw，不能返回 stub 假成功

**适用情境**: LLM provider 桥接失败、API 超时、key 无效、模型不可用等场景。

**铁律**: LLM 调用失败时必须 throw error，不能返回 stub 占位文本（尤其是 `finishReason: 'stop'`）。让 router 的 fallback 链能触发，让调用方能检测到失败。

**反例**:
```typescript
// 错误：返回 stub 假成功
return {
  content: '[bridge unavailable]',
  finishReason: 'stop',  // ← 假成功！
};
```

**正例**:
```typescript
// 正确：throw error，让 router fallback
throw new Error('bridge unavailable');
```

**关联铁律**：
- Loop Engineering 铁律 2"循环里必须有说不的" — stub 假成功让"说不"失效
- E74（防 LLM 自评自满）— stub 让 LLM 以为自己成功了
- E79（跨模块衔接必须双向标记）— router 依赖 provider throw error 来触发 fallback
