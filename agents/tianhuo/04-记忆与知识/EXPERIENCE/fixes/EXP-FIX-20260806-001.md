# EXP-FIX-20260806-001 · verify-* 测试链式调用必须 pid+Date.now() 唯一化临时目录

## 背景

2026-08-06 main 分支推送至 tianshu/main 时，pre-push hook 触发 full 档链式调用（含 test:all → test→contracts→verify 串行）。`verify-l2-token-accounting.ts` 用固定路径 `test-tmp-l2-token/test-l2-token.db`，前次异常退出残留 db 触发：
- `Migration failed: UNIQUE constraint failed: schema_migrations.version`
- `Auto-restore also failed: EBUSY: resource busy or locked`（better-sqlite3 native 锁未释放）

单独跑 `node scripts/run-verify-tests.mjs` 全部 24/24 通过；但 pre-push 链式跑 24/24 失败（verify-l2-token-accounting 单点失败）。

## 解决路径

1. 临时目录路径唯一化：`tmpDir = test-tmp-l2-token-${process.pid}-${Date.now()}`
2. 进入测试前 `rmSync(tmpDir, { recursive: true, force: true })` 清理残留
3. `mkdirSync(tmpDir, { recursive: true })` 创建新目录
4. 退出时 `rmSync(tmpDir, { recursive: true, force: true })` 清理
5. 与 runtime/test/ 其他 verify-* 测试约定对齐（verify-budget-order 等已用 `Date.now()` 唯一化）

## 根因

**verify 测试"独立可跑"vs"链式可跑"的隔离标准未文档化**——单文件独立跑（`run-verify-tests.mjs` 串行）能过；但 test:all 链式调用（test→contracts→verify 跨文件，可能共享进程状态或目录）暴露固定路径 bug。
- 机制层：M3 进阶-6 新增 verify-l2-token-accounting 时未沿用历史约定（verify-budget-order 等已用 `Date.now()` 唯一化）
- 根因层：约定存在但未写入测试模板/脚手架；新增测试靠"开发者记忆"沿用

## 修复与预案

- 修复：commit `8f682ad fix(test): verify-l2-token-accounting 临时目录唯一化避免 test:all 状态污染`（最小修复 6+2 行，不动业务逻辑）
- 预案：
