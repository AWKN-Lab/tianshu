# 服务器盘点清理与部署备份策略重构｜脱敏版 PDCA 报告

**复盘时间**：2026-08-06  
**安全状态**：已脱敏；不含主机地址、账户、密钥路径、内部绝对路径或完整哈希

## P｜目标

1. 盘点服务器项目、服务和主要磁盘占用。
2. 对旧版本和历史归档执行可恢复清理。
3. 修正会持续制造服务器端备份的过期部署规则。
4. 保证破坏性操作前具备备份、完整性检查和用户授权。

## D｜执行事实

- 发现某业务项目长期保留旧 release 和大型历史归档，导致磁盘利用率进入告警区间。
- 首次尝试通过 PowerShell 文本管道传输二进制归档失败，产物为零字节。
- 改为服务器端生成归档文件，再使用二进制安全协议下载。
- 本地与服务器完整性检查一致后，删除已确认的旧版本和临时文件。
- 部署规则由“每次在服务器复制备份”修订为“Git/制品仓库作为版本来源，服务器只保留运行所需版本和有限回滚版本”。

## C｜关键原因

### 1. 二进制传输失败

PowerShell 管道采用对象和文本语义，不能假设与 Unix 原始字节管道等价。大文件应使用 `scp`、SFTP 或受控制品通道，传输完成后进行完整性验证。

### 2. 服务器持续堆积

堆积并非单次执行疏漏，而是旧部署规则持续生成备份包和 `.bak` 目录。只清理存量会复发，必须先修改制造规则。

## A｜固化规则

### 服务器旧版本回收 SOP

1. 生成待清理清单。
2. 确认 Git、制品仓库或本地归档中存在恢复来源。
3. 服务器端生成归档，使用二进制安全协议下载。
4. 比较完整性校验结论；报告只记录“匹配/不匹配”，不保存完整哈希。
5. 获得破坏性操作授权后删除。
6. 验证当前服务、磁盘和回滚路径。

### 部署保留策略

- Git 和制品仓库承担长期版本保留。
- 服务器只保留当前运行版本和明确数量的回滚版本。
- 禁止无生命周期策略的长期 `.bak`、全量目录复制和临时归档堆积。
- 发布前先固化上一稳定版本，再部署新版本。

## 风险与未完成项

- 备份文件应执行恢复可读性检查，单纯哈希一致不足以证明可恢复。
- 服务器上的旧凭据、连接串或历史脚本如曾被写入报告或日志，应视为暴露并轮换。
- 后续缓存和日志清理由独立授权任务处理，不与本次经验提交混合。
