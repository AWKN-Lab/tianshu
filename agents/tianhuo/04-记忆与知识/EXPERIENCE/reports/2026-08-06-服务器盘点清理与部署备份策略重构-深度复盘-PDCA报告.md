## 4. C｜Check 检查

### 4.1 原因分析（5Why）

**问题 1：PowerShell 管道下载二进制失败（0 字节 + 超时）**

1. 为什么下载失败？→ `Set-Content -AsByteStream` 报"内容必须为 byte 类型"，文件 0 字节
2. 为什么报错？→ PowerShell 管道把 `ssh` 原生 stdout 按**文本行流**处理，到不了字节模式
3. 为什么用管道？→ 想一条命令"打包+下载"，没把传输通道的二进制安全性当独立变量
4. 为什么没想到先打包？→ 注意力全在"下载目标"上，跳过"传输格式"设计
5. **根因**：Windows PowerShell 的管道是文本协议，与 Unix 式二进制 stdout 管道语义冲突；SSH 大文件二进制传输必须走 scp/rsync，或"服务器端先落盘文件 → scp"

**问题 2：服务器为什么堆积 954M 备份包 + 1.8G 旧版本？**

1. 为什么堆积？→ 每次部署按规则执行备份，长期只增不减
2. 为什么按规则执行？→ E-A10"备份（必须）"直接要求 `cp -r assets assets.bak-<TS>`
3. 为什么规则这么写？→ 2026-05 时代服务器端备份是唯一回滚手段（教训：cp 5 分钟回滚）
4. 为什么现在不合理？→ GIT 已成所有项目备份源，服务器端备份冗余且占磁盘
5. **根因**：技能规则没有随 GIT 工作流演进而更新——**规则驱动产物，修规则才治本**（单次清理只是治标）

### 5.2 风险与应对

| 风险 | 触发条件 | 后果 | 应对策略 |
|------|---------|------|---------|
| prev 分支未固化就推 main | 发布流程跳过第 1 步 | 上一版丢失 | 规则里加"顺序不可颠倒"警示 + 发布前检查 |

### 5.4 沉淀与复用

**SOP**：
1. **服务器旧版本回收 SOP**：服务器 `tar czf` → scp 下载本地 → SHA256 双方比对 → 删除 → 记录
2. **GIT 即备份发布 SOP**：固化 prev → 推 main → （可选）tag → 服务器 releases 保留当前+上一版

**原则**：
1. 服务器磁盘只跑业务，不承担备份（GIT 即备份，2026-08-06 起）
2. 规则驱动产物——堆积类问题先查技能规则是否过期，修规则比逐次清理治本
3. Windows 二进制传输永远 scp，不用 SSH 管道

**可迁移经验**：
- 二进制传输坑 → 适用任何"服务器⇄Windows 本机大文件"场景（含数据库 dump、媒体资产）
- 规则演进滞后 → 适用所有技能文档（定期对照当前工作流审查"曾经合理"的规则）

**下次先做 3 件事**：
1. 大文件下载先想"传输通道二进制安全"（scp/rsync），不碰 SSH 管道
2. 清理类任务先查技能规则是否还在要求"制造垃圾"（修规则治本）
3. 破坏性删除前：本地备份 + SHA256 校验 + 用户确认三件套
