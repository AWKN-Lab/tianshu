| Gap | 期望 | 现实 | 影响 |

### 4.3 原因分析（5Why + 假设驱动 双法）

**方法选择**：盲区用 5Why 探根因；YAML 冒号用假设驱动。

#### 三层根因（Gap1，门禁链自检盲区）

| 层 | 内容 | 证据 |
|----|------|------|
| **表层** | Select-CheckMode 不匹配 `scripts/` `.githooks/` `.github/workflows/` 路径 | D#11-12 实测 |
| **机制** | 选档路径按"业务领域"建表（agents/capabilities/runtime/integrations-open-code-review），未把"门禁链 = 修门禁的脚本"作为一类需保护资产列入；agents 档检查脚本只校验 `agents/` 下结构化资产，不校验仓库级脚本 | Select-CheckMode 代码 |
| **根因** | **检查设计按"被保护对象"分档（业务域），未按"保护机制自身"分档（门禁链也是被检查对象）**。本质是设计假设：检查覆盖范围 = 业务域，未把基础设施层（门禁脚本）纳入。盲区存在是设计层面的"假设缺口"，不是 bug | E33 漂移预防双门禁（部分同根：spec 覆盖 ≠ 实际覆盖） |

#### 三层根因（Gap2，YAML 冒号陷阱）

| 层 | 内容 | 证据 |
|----|------|------|
| **表层** | `- name: Light gate: TypeScript typecheck (contract 档核心)` 中 `gate:` 冒号+空格 | D#6 js-yaml 报错位置 |
| **机制** | GitHub Actions step name 是 plain scalar（无引号），YAML plain scalar 中 `: ` 是映射分隔符标记；开发者写 step name 时按"自然语言标题"直觉起草，忽略 YAML 转义规则 | YAML 1.2 spec + D#7 修复（加单引号） |
| **根因** | **"自然语言字段在 YAML 里是 plain scalar"是隐性约定，无显式教学**。GitHub Actions 文档示例全部用无冒号标题，掩盖了"含特殊字符要加引号"的基础规则 | 经验缺失（EXP-DRV-006 填补） |
