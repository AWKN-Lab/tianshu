## EXP-022：LLM Provider管理

- **ID**: EXP-022
- **评级**: A级
- **场景**: API调用失败或超时的处理

### 多Provider Fallback

```javascript
// 多 Provider Fallback
// 优先级：minimax > moonshot > openai
const providers = {
  minimax: { timeout: 180000, priority: 1 },  // 180秒
  moonshot: { timeout: 60000, priority: 2 },   // 60秒
  openai: { timeout: 120000, priority: 3 }      // 120秒
};

// Fallback 触发条件
// - 超时
// - 账户停用
// - 错误响应
```

### 常见问题处理

| 问题 | 根因 | 快速定位 | 解决方案 |
|------|------|---------|---------|
| API超时 | Provider问题 | 检查Provider状态 | 启用fallback |
| 账户停用 | 余额不足 | 检查账户 | 切换备选Provider |
| 错误响应 | 接口变更 | 查看错误信息 | 降级到稳定版本 |

## EXP-023：记忆检索最佳实践

- **ID**: EXP-023
- **评级**: A级
- **场景**: 复杂任务需要获取历史记忆

### 强制检索场景

```
【强制检索场景】
1. 复杂问题（超过5分钟）
2. 多步骤任务
3. 跨模块修改
4. 历史问题重复出现
5. 涉及生产环境操作
6. 涉及删除/覆盖/重写操作
```

### 检索流程

```
【检索流程】
memory_search(查历史) → web_search(查最新) → 整合答案

【降级策略】
memory_search失败 → 降级为Read直接读取文件
```

### 检索结果整合

```
1. memory_search 返回相关记忆条目
2. 筛选与当前任务最相关的3-5条
3. 结合web_search的最新信息
4. 整合成完整的上下文方案
```
