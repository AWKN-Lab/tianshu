# EXP-028: 算法确定性+LLM不确定性分工模式

> **经验等级**: S级
> **来源项目**: 大宗师项目（人生决策宗师）
> **提取时间**: 2026-04-22
> **适用场景**: 命理算法排盘、AI对话生成

---

## 核心洞察

**问题**: 命理判断系统中，两类任务有截然不同的特性：
- **算法任务**（八字排盘、六壬起课）：需要100%精确，相同输入必须产生相同输出
- **LLM任务**（断事解读、运势分析）：天然具有不确定性，但需要风格一致性

**旧方案**: 全部交给LLM处理，导致结果不稳定、推理过程不可追溯
**新方案**: 算法负责确定性计算，LLM负责不确定性解读，两者分工明确

---

## 设计原则

### 原则1: 算法处理规则明确的计算

```
输入(出生时辰) → 算法引擎 → 输出(八字四柱、十神、纳音)
```

- **特性**: 输入确定 → 输出确定，数学可证明
- **边界**: 所有能用规则穷举的场景，都应该算法化
- **优势**: 结果稳定、可测试、可审计

### 原则2: LLM处理规则模糊的生成

```
输入(八字结构+用户问题) → LLM推理 → 输出(命理解读)
```

- **特性**: 语义理解、语境推断、多元素综合
- **边界**: 需要主观判断、需要生成自然语言的场景
- **优势**: 表达灵活、语义丰富、风格可控

### 原则3: 算法结果作为LLM的context

```
算法输出 → 构建prompt context → LLM推理 → 最终答案
```

- **关键**: LLM看到的永远是算法输出的结构化数据
- **好处**: LLM的"幻觉"不影响算法准确性
- **边界**: 禁止LLM直接修改算法结果

## 大宗师项目的实际应用

### 八字排盘（算法主导）

```typescript
// 确定性计算，绝对不能LLM介入
function calculateBazi(birthTime: DateTime): BaziResult {
  // 1. 真太阳时校正（算法）
  const trueSolarTime = adjustTrueSolarTime(birthTime);

  // 2. 日柱计算（算法）
  const dayZhu = calculateDayZhu(trueSolarTime);

  // 3. 月柱计算（算法）
  const monthZhu = calculateMonthZhu(trueSolarTime);

  // 4. 年柱计算（算法）
  const yearZhu = calculateYearZhu(trueSolarTime);

  // 5. 时柱计算（算法）
  const hourZhu = calculateHourZhu(trueSolarTime);

  // 结果：100%确定性
  return { yearZhu, monthZhu, dayZhu, hourZhu };
}
```

### 命理解读（LLM主导）

```typescript
// 不确定性生成，依赖LLM能力
async function interpretBazi(bazi: BaziResult, question: string): Promise<string> {
  const prompt = buildPrompt(bazi, question);

  // LLM负责：语义理解、多元素综合、风格生成
  const interpretation = await llmGateway.chat(prompt);

  return interpretation;
}
```

## 关键约束

1. **算法结果不得被LLM修改** - LLM只能解读，不能重算
2. **算法输入必须校验** - 垃圾进、垃圾出，但算法不应该崩溃
3. **LLM prompt必须包含算法结果** - 不能让LLM"凭感觉"
4. **边界明确** - 排盘用算法，断事用LLM，禁止混用

## 验证方法

### 算法部分验证

```bash
# 相同输入必须产生相同输出
输入: 2024-01-15 14:30 北京时间
输出: 癸卯年 甲寅月 壬午日 丙午时

# 再执行一次
输入: 2024-01-15 14:30 北京时间
输出: 癸卯年 甲寅月 壬午日 丙午时  # 必须完全一致
```

### LLM部分验证

```bash
# 风格一致性检查
输入: 同一八字 + 不同时间问相同问题
期望: 核心判断一致，表达可以有变化

# 不一致判定
核心吉凶判断矛盾 → LLM prompt问题
用词风格不一致 → 需要固定style guidelines
```

## 反面教材

**错误做法**: 让LLM直接计算八字
- LLM的"幻觉"会导致排盘错误
- 相同问题多次询问可能得到不同结果
- 无法向用户解释推理过程

**正确做法**: 算法算好，LLM解读
- 排盘100%准确（算法保证）
- 解读风格一致（prompt控制）
- 推理过程可追溯（算法结果可查）

## 迁移到天火智能体

**适用场景扩展**:
- 代码生成: 算法确定函数签名，LLM生成实现
- 文档生成: 算法确定结构，LLM生成内容
- 测试生成: 算法确定边界，LLM生成用例

**核心原则**:
> 当一个任务可以拆分为"确定性计算"+"创造性生成"时，必须分离。算法保证正确性，LLM保证灵活性。
