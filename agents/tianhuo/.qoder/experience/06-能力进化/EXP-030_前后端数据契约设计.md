# EXP-030: 前后端数据契约设计

> **经验等级**: A级
> **来源项目**: 大宗师项目（人生决策宗师）
> **提取时间**: 2026-04-22
> **适用场景**: 前后端分离架构、API设计、数据流定义

---

## 核心洞察

**问题**: 前后端分离项目中，数据格式不一致导致的联调返工是最大的时间浪费：
- 前端期望的字段名与后端返回的不一致
- 字段类型不匹配导致运行时错误
- 缺少必要字段导致UI无法渲染
- 字段变更没有同步通知

**新方案**: 契约先行 + 类型固化 + 自动化校验

## 契约设计原则

### 原则1: 契约文件集中管理

```
项目结构
├── contracts/           # 契约目录
│   ├── index.ts        # 统一导出
│   ├── bazi.contract.ts
│   ├── user.contract.ts
│   └── consultation.contract.ts
├── frontend/
│   └── src/
│       └── types/     # 引用contracts
└── backend/
    └── src/
        └── dto/       # 引用contracts
```

### 原则2: 契约使用TypeScript类型

```typescript
// contracts/user.contract.ts
import { z } from 'zod';

// Zod Schema 用于运行时校验
export const UserProfileSchema = z.object({
  id: z.string().uuid(),
  nickname: z.string().min(1).max(50),
  avatar: z.string().url().optional(),
  birthInfo: z.object({
    birthDate: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),
    birthTime: z.string().regex(/^\d{2}:\d{2}$/),
    timeAccuracy: z.enum(['precise', 'approximate']),
    timezone: z.string(),
    location: z.string().optional(),
  }),
});

// TypeScript类型 从Zod推断
export type UserProfile = z.infer<typeof UserProfileSchema>;
```

## API设计规范

### RESTful URL设计

```
GET    /api/consultations/:id      # 获取咨询详情
POST   /api/consultations          # 创建咨询
DELETE /api/consultations/:id     # 删除咨询

GET    /api/bazi/:userId           # 获取八字
POST   /api/bazi/calculate         # 计算八字

GET    /api/daliuren/:userId       # 获取六壬
POST   /api/daliuren/calculate    # 起课
```

### 响应格式统一

```typescript
// 统一响应格式
interface ApiResponse<T> {
  success: boolean;
  data?: T;
  error?: {
    code: string;       // 业务错误码
    message: string;    // 用户可见错误信息
    details?: any;      // 调试信息（仅开发环境）
  };
  meta?: {
    timestamp: number;
    requestId: string;
  };
}

// 成功响应
{
  success: true,
  data: { ... },
  meta: { timestamp: 1713772800000, requestId: "xxx" }
}

// 错误响应
{
  success: false,
  error: { code: "BAZI_INVALID_TIME", message: "出生时间格式错误" }
}
```

## 字段命名规范

### 驼峰 vs 蛇形

```typescript
// 后端存储: 蛇形（数据库惯例）
database_column: "birth_date"

// API响应: 驼峰（JSON惯例）
json_response: "birthDate"

// 前端使用: 驼峰（TypeScript惯例）
typescript: "birthDate"
```

### 命名约定

| 场景 | 格式 | 示例 |
|------|------|------|
| 数据库 | snake_case | birth_date |
| API请求/响应 | camelCase | birthDate |
| TypeScript | camelCase | birthDate |
| 用户界面 | 中文/本地化 | 出生日期 |

## 数据校验策略

### 前端校验（用户体验）

```typescript
// 使用Zod前端校验
const formSchema = z.object({
  birthDate: z.string().regex(/^\d{4}-\d{2}-\d{2}$/, '日期格式错误'),
  birthTime: z.string().regex(/^\d{2}:\d{2}$/, '时间格式错误'),
});

// 表单提交前校验
const result = formSchema.safeParse(formData);
if (!result.success) {
  showFieldErrors(result.error.flatten());
  return;
}
```

### 后端校验（安全防线）

```typescript
// 同样的Schema，后端二次校验

export class BaziController {
```
