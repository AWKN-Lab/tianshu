# Token 控制策略

> 版本：v1.0 ｜ 日期：2026-07-09 ｜ 状态：设计稿

## 结论先行

token 是硬约束（铁律 5）。6 条策略控制用量：选对层级、选对模型、确定性写脚本、先小规模试跑、间隔匹配频率、盯用量。超限走 3-strike 协议，不靠模型自觉。

---

## 一、6 条策略详细落地

### 策略 1：选对层级

| 做法 | 说明 |
|------|------|
| 原则 | 能 L1 不 L2，能 L2 不 L4 |
| 理由 | 层级越高，轮数越多，token 越烧 |
| 判断 | 单步能完成 → L1；有明确停止条件 → L2；需定时 → L3；多 agent 自治 → L4 |

**反例**：用 L4 跑一个单次调研 → 浪费 5x token

**正例**：调研用 L1 `/skill awkn-调研员`，一次搞定

### 策略 2：选对模型

| 任务类型 | 推荐模型档位 | 理由 |
|---------|------------|------|
| 简单分类 / 路由 | 小模型 | 不需要推理深度 |
| 代码生成 / 重构 | 中模型 | 平衡质量与成本 |
| 复杂设计 / 审核 | 大模型 | 需要推理深度 |
| 确定性判断 | 无模型（脚本） | 0 token |

**运行时配置**：每个 Skill 的 manifest.json 可指定 `modelTier`，orchestrator 按档位路由。

### 策略 3：确定性写脚本

| 做法 | 说明 |
|------|------|
| 原则 | 能用脚本判断的不用模型 |
| 适用 | 类型检查、测试、lint、计数、diff |
| 工具 | tsc / pytest / eslint / jq / diff |
| 收益 | 0 token，且可复现 |

**反例**：让模型读测试输出判断"是否通过" → 烧 token 还可能误判

**正例**：脚本解析 pytest 输出，0 failed 即 PASS → 0 token

### 策略 4：先小规模试跑

| 做法 | 说明 |
|------|------|
| 原则 | 新 Loop 先 3 轮试跑，看趋势再放量 |
| 参数 | `--max-rounds 3 --budget 30k` |
| 观察 | 单轮 token、gate 通过率、收敛趋势 |
| 决策 | 趋势好 → 放大到 20 轮；趋势差 → 调意图或换 Skill |

### 策略 5：间隔匹配频率

| 做法 | 说明 |
|------|------|
| 原则 | L3 定时 Loop 的间隔要与任务变化频率匹配 |
| 反例 | 依赖每小时变一次，却每分钟巡检 → 浪费 |
| 正例 | 依赖每小时变一次，每 30 分钟巡检 → 合理 |
| 建议 | 巡检间隔 ≥ 变化间隔 / 2 |

### 策略 6：盯用量

| 做法 | 说明 |
|------|------|
| 原则 | 每轮看 token，每 Loop 看总量 |
| 监控指标 | 见第三节 |
| 阈值 | 单轮达预算 80% → 警告；100% → 3-strike |
| 工具 | 运行时内置 token 计数器 + budgetGate |

## 二、L1-L4 各层级 token 预算建议

| 层级 | 单轮预算 | 单 Loop 总预算 | 建议 max-rounds | 理由 |
|------|---------|--------------|----------------|------|
| L1 | 10-30k | 30k | 1 | 单次调用，无循环 |
| L2 | 30-50k | 200k | 20 | 多轮收敛，需余量 |
| L3 | 20-40k | 100k/次触发 | 单次 10 | 每次触发独立预算 |
| L4 | 50-100k | 500k | 50 | 多 agent 长任务 |

### 预算分配建议（L2 为例）

| 用途 | 占比 | token（总 200k） |
|------|------|----------------|
| 执行类 Skill | 60% | 120k |
| 验证类 Skill（审核/检查） | 20% | 40k |
| Gate 命令执行 | 0% | 0（脚本跑） |
| orchestrator 调度 | 10% | 20k |
| 缓冲 | 10% | 20k |

## 三、token 超限 3-strike 协议

**铁律 5**：token 是硬约束。超限不靠模型自觉，走协议。

### Strike 1：警告

| 触发 | 动作 |
|------|------|
| 单轮 token 达预算 80% | 记警告日志，继续本轮 |
| 单 Loop 累计达总预算 80% | 记警告日志，提示用户 |

### Strike 2：降级

| 触发 | 动作 |
|------|------|
| 单轮 token 达预算 100% | 本轮强制结束，进入下一轮 |
| 降级措施 | 下一轮模型档位降一级（大→中→小） |
| 降级措施 | 下一轮禁用非必要 Skill（只留执行+验证） |

### Strike 3：停止

| 触发 | 动作 |
|------|------|
| 连续 2 轮达预算 100% | 停止 Loop |
| 单 Loop 累计达总预算 100% | 停止 Loop |
| 停止后 | 调用 awkn-复盘总结 写回失败原因 |

### 协议流程

```
轮内监控：
  80%  → Strike 1 警告
  100% → Strike 2 本轮结束 + 降级
连续 2 轮 100% → Strike 3 停止

Loop 级监控：
  80%  → Strike 1 警告
  100% → Strike 3 停止
```

## 四、用量监控指标

### 4.1 核心指标

| 指标 | 含义 | 采集点 |
|------|------|-------|
| 总 token | 整个 Loop 累计 | 每轮结束累加 |
| 单轮 token | 单个 Turn 消耗 | 每轮结束记录 |
| 单 agent token | 单个 Skill 调用消耗 | Skill 调用结束记录 |
| 单位产出 token | token / 改动行数 | Loop 结束计算 |

### 4.2 输出格式

每轮结束输出 JSON：

```json
{
  "loopId": "loop-2026-07-09-001",
  "round": 5,
  "roundTokens": 12340,
  "totalTokens": 56700,
  "budgetUsed": 0.28,
  "skillBreakdown": {
    "awkn-工程师": 8000,
    "awkn-审核": 4000,
    "awkn-执行检查": 340
  }
}
```

### 4.3 监控看板字段

| 字段 | 说明 |
|------|------|
| loopId | Loop 标识 |
| 当前轮 / 最大轮 | 进度 |
| 累计 token / 预算 | 用量 |
| 预算使用率 | 百分比 |
| gate 通过率 | 质量信号 |
| 预计剩余 token | 趋势预测 |

## 五、省钱正反例

### 5.1 正例

| 场景 | 做法 | 收益 |
|------|------|------|
| 类型检查 | 用 tsc 脚本，不用模型 | 0 token |
| 测试结果判断 | 解析 pytest JSON，看 failed 数 | 0 token |
| 简单路由 | 用 awkn-意图理解（小模型） | 省 70% |
| 调研任务 | L1 单次 `/skill awkn-调研员` | 不进 Loop |
| L3 巡检 | 间隔匹配变化频率 | 不空转 |
| 新 Loop | 先 3 轮试跑 | 早发现趋势差 |

### 5.2 反例

| 场景 | 错误做法 | 后果 |
|------|---------|------|
| 类型检查 | 让模型读 ts 文件判断类型 | 烧 token 还可能错 |
| 测试结果 | 让模型读测试输出"判断是否通过" | 烧 token，不可复现 |
| 简单路由 | 用大模型做意图分类 | 大材小用 |
| 调研任务 | 起 L4 Loop 跑调研 | 5x 浪费 |
| L3 巡检 | 每分钟查每小时变的依赖 | 60x 空转 |
| 新 Loop | 直接 20 轮全量 | 趋势差时全亏 |
| gate 判定 | 让模型"评估代码质量" | 主观且烧 token |

## 七、预算调整规则

| 场景 | 调整 |
|------|------|
| 连续 3 轮 gate 全 PASS 且未达目标 | 下一轮预算 +20%（接近收敛） |
| 连续 3 轮同一 gate FAIL | 下一轮预算 -30%（卡点，少烧） |
| 进入 L4 阶段切换 | 重置单轮预算到阶段默认值 |
| 3-strike Strike 2 触发 | 下一轮预算 -50% + 降档 |

---

## 八、与 budgetGate 的联动

| 时机 | budgetGate 动作 |
|------|----------------|
| 每轮开始 | 检查剩余预算，<10% 则直接 Strike 1 |
| 每轮结束 | 累加本轮 token，检查是否触发 Strike |
| Loop 结束 | 输出总量 + 单 agent 分布 |

详见 `quality-gates.md` 第 2.7 节。
